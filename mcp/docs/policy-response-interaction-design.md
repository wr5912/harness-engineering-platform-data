# 策略与应急交互设计

固定调用链采用两个已发布组合：[策略变更](../compositions/policy-change/docs/README.md)和[应急动作](../compositions/emergency-action/docs/README.md)。咨询、发现、语义选择及独立的原号查询继续使用原始 AISOC 工具与 Skill。目标 Harness 为 `EXP-security-operations-expert-027-f-r5efdc136f237`；原始工具分组为 `policy-response`，固定发布版本通过分组 `policy-response-acceptance` 提供调用。装载与验收结果见目标 Experiment 的 Run，不以本文证明业务通过。

设计方法见[组合开发方法](../../.agents/skills/mcp-composition/references/development.md#先判断是否需要组合)。接口参数、枚举和响应以 MCP 管理中原始 AISOC 连接的实时 Schema 及实际回执为准；本文只维护用户任务的调用顺序、数据用途和停止位置，不复制 DTO 或实现。

## 智能体与固定调用链的边界

Skill 负责理解当前意图、咨询、选择和必要补问；确定的接口衔接、数据整理、并发和错误恢复交给组合。组合直接调用 AISOC，不增加本地业务台账，也不替代上游校验、草稿或审批。

| 组合 | 已明确输入后的固定接口链 | 交付与停止位置 |
| --- | --- | --- |
| 策略变更 | 设备及参数合同 → 真实 preview → 按授权创建原任务 → 预检、提交 → 核对实际批准状态 → 执行一次 → 原任务回读 | 按本轮意图停在预览、草稿或授权下发；遇上游审批返回原关联，不代替审批人。结果未知保留原号，不重建或自动重放 |
| 应急动作 | 当前动作定义及合格目标 → 必要的 Agent 或实时扫描模板 → 参数核对 → 按授权准备、预览或执行 → 原请求回读 | 准备无写入；预览必须取得上游真实指令；仅创建扫描任务须有独立上游能力，没有则说明缺口，不用执行后取消替代 |

咨询阶段仍可直接查询候选；不能在用户尚未确定目标或动作时强行进入固定执行链。批量场景复用同一业务片段并整理逐项结果，是否需要独立批量入口取决于实际输入输出及上游 changes 合同。提交、审批、执行和恢复遵循用户当轮授权，不合并成一次默认全执行。

对比以同一输入的原始工具链为基线，核对结果一致性、模型往返、传输量、上游请求和耗时，无实测不宣称性能收益。

## 用户任务与结束位置

用户通过智能体说明目标。智能体连续完成查询、选择、必要的数据整理和结果解释，AISOC 承担规则渲染、业务校验、冲突分析、草稿、审批和执行状态。会话保留原业务 ID 和必要上下文，不建第二份业务台账。

| 用户意图 | 本轮结果 | 业务写入边界 |
| --- | --- | --- |
| 咨询、发现设备／问题／事件、分析建议 | 有来源和覆盖范围的事实或建议 | 无 |
| 预览，不保存 | 上游真实预览及缺口 | 仅已核实无副作用的预览调用 |
| 草案，不提交 | AISOC 草稿保存后按原 ID 回读 | 只创建草稿 |
| 提交审批 | 原任务提交受理及审批关联 | 不自动批准或执行 |
| 下发／执行 | 授权范围内的真实业务受理及结果 | 不越过上游实际审批；不增加平台确认器 |
| 应急方案，不执行 | 动作、目标、参数、影响和恢复条件 | 无；不虚构应急草稿号 |
| 查进度／结果 | 原 ID 的当前状态 | 不续办写操作 |
| 修改／取消／恢复 | 先查原状态，再走已具备的上游能力 | 修改会话不等于撤销已受理动作 |

已有信息足够就直接办理。合法源目 IP／CIDR 不强制先查为资产；执行设备使用真实 deviceId。只在影响业务效果的歧义、无法查询的必填语义、范围扩大或上游确需人工介入时询问。输入完整不重复确认，接口故障不能伪装成用户信息不足。

## 从不知道对象开始

| 用户当前知道什么 | 先查什么 | 如何继续 |
| --- | --- | --- |
| 不知道有哪些设备 | `search_graph_assets`，批量按真实目录及成员查询 | 展示身份、地址、类型、归属和分页范围；只咨询不建任务 |
| 不知道哪些设备有问题 | 原巡检结果、资产状态、告警或正式诊断能力 | 保留证据时间、异常依据、覆盖与未知；资产搜索不证明异常 |
| 不知道哪些事件需要关注 | 当前真实事件列表与筛选工具 | 展示真实事件、时间和排序依据，不自动研判或处置 |
| 选择“第二台／刚才那个事件” | 绑定同一会话候选的真实身份，查必要详情 | 进入用户要求的研判、故障、巡检或策略／应急；不要求抄内部 ID |
| 根据分析要求草稿／处置 | 复用原证据，补查执行设备和动作能力 | 区分故障资产、流量源目、攻击源与执行点，不把异常直接推成封禁理由 |

发现能力按实时目录使用，不新增虚构接口或候选台账。分页不完整、空结果、读取失败分别说明；旧结果过期时刷新受影响事实。候选变化后按真实身份核对，不能沿用新列表的同一序号。此入口同样适用于威胁研判、故障和巡检；评测来源统一为 Agent 的 evaluation.md。

## 策略：定位 → 真实预览 → 草稿

1. 已给防火墙或其他执行设备：`get_ingest_dispatch_dispatchable_devices` 按实际配置种类／操作查询合格设备，用返回的 IP、名称、deviceId 定位。唯一匹配继续；空结果说明不支持或范围缺口，多个执行点且语义不唯一时才询问。已取得有效身份不重复 graph→master→ingest 映射。
2. 已有适用配置和真实参数合同就复用；确需发现配置时调用 `get_admin_dispatch_task_policy_configs`，确需输入字段时调用 `get_admin_dispatch_task_input_fields`。从用户流量意图填写实际字段，不猜厂商命令、模板或缺省枚举。
3. 调用 `preview_admin_dispatch_task`。读取上游真实配置渲染、校验与已有策略分析；不在平台重新生成命令或重复做冲突引擎。仅预览到此结束。失败时保留已知输入和失败原因；不可渲染或必要校验不通过时不建草稿。
4. 用户要求草案时，用同一已预览意图调用 `create_admin_dispatch_task`，再以返回的原 ID 调用 `get_admin_dispatch_task_by_id` 核对设备、明细、状态和保存事实。只创建成功不能表述为已提交、审批通过或设备生效。

调用数按真实任务计量：已有配置上下文时可缩短；需要配置发现、复杂批量或大量返回时按共同方法评估组合，不将所有辅助查询变成固定前置步骤。

### 批量策略

按用户给定的 IP 集合、资产分组、业务系统或组织范围查真实成员。部门只是范围选择方式，用户功能统一称“批量策略”。遵循真实分页和上游批量 changes 能力，按设备能力分组并保留合格、失败和未覆盖项；不逐台创建本地计划或任务。

每项使用实际策略输入及真实预览，必要的独立只读查询可有界并发；有依赖的调用顺序执行。草稿使用上游允许的多明细请求；部分失败不能伪装全部通过，也不能默默扩大／缩小用户范围。只保存合格子集会改变用户原意时说明差异并取得必要选择。

### 提交、审批、执行及查询

先按原 task ID 回读当前状态和真实要求。确需时走 `precheck_admin_dispatch_task`；用户要求提交才调用 `submit_admin_dispatch_task`。提交返回受理不等于已审批。

需要审批时，从原任务取得业务／流程关联，`get_workflow_task_mine` 按真实分页查找属于该业务的待办，不取第一条、不凭名称猜 ID。列表已有充分关联和必要详情时直接使用；不足时才 `get_workflow_task_by_task_id`。`approve_workflow_task` 只办理用户明确授权且当前身份允许的原待办。凭据／审批人缺失时返回真实阻塞，不绕过审批。

用户授权执行且上游状态允许时调用 `execute_admin_dispatch_task`，随后按原任务查询；恢复／回滚先读取原任务和影响，只有上游提供且授权允许时才 `rollback_admin_dispatch_task`。不以撤销草稿冒充设备规则回滚。

### 三个非默认接口

| 接口 | 当前用途 |
| --- | --- |
| `get_reachability_acl_hit` | 从普通新增策略必经步骤移除；保留现有巡检和明确的覆盖验证场景 |
| `get_admin_entity_data` | 不默认全量读已有规则；只有上游预览不足且任务确需独立分析时按范围、分页查询 |
| `get_workflow_task_by_task_id` | 待办列表与原业务关联不足时补查，不强制每次调用 |

这三项不是外部接口删除清单。证据不足时不能宣称“无冲突、无重复、全覆盖”；预览和草稿也不证明业务可达。

## 应急：动作目录 → 目标 → 执行或停在方案

1. 读取当前响应动作目录／资源，确定 actionKey、输入 Schema、目标类型、影响和恢复能力；无适用动作就说明能力缺口，不造工具名。
2. `get_resp_actions_target_candidates` 取得该动作的合格目标，使用真实设备身份；只有 EDR／主机动作确需 agentId 时才 `get_resp_actions_device_agents`。普通设备动作不强制套主机代理链。
3. 将用户意图及已选目标映射到该动作的实际 Schema。仅方案时返回建议与缺项，不调用 execute，也不创建本地应急草稿。建议可执行性不足时明确说明，不能包装成真实预检通过。
4. 用户明确要求执行时，生成符合上游要求且本次动作稳定的 requestId，用实际 target／params 调用 `execute_resp_agent_actions`，再 `get_resp_agent_actions_executions` 按同一 requestId 查询。params 不混入路由字段。受理、运行、部分失败、完成分别表述。
5. 动作后修改、取消、恢复先查询原请求；只有上游已提供相应能力时才能办理。恢复是有明确目标和授权的新业务动作，不通过删除本地记录模拟。

## 容错与恢复

- 校验目标身份、必要输入及真实返回。分页到实际范围完成；大响应保留事实和来源，不能截断后声称完整。独立查询部分失败时保留已完成项，失败子项不阻塞无依赖的只读工作。
- 只读临时错误可以有限重试；认证、业务校验、歧义不盲重试。查询耗时超过预算就返回原号与已知状态，不建调度器。
- 写请求只在当前授权内发起。超时、断连或丢回执属于结果未知，先按原 task ID／requestId 查询，不能换号、重建草稿或自动重放。创建草稿未取得 ID 时，用实际任务查询和本次关联寻找；不能唯一确认就说明未知并停在此处。
- 会话和已有调用回执保存原号线索，业务状态始终回读 AISOC。不用平台 operation_id、修订、摘要或命令槽作为业务必填。
- 目标、范围、配置或动作变化后刷新受影响的事实与预览；不能用旧预览证明新请求。已发出的操作按原号收尾，取消新指令不能撤销已受理写入。

## 验证边界

先验证原始工具目录、输入输出与只读调用，再通过目标版本的真实多轮任务验证发现、选择、预览、停止位置、结果解释和原号恢复；隔离测试只替换外部 AISOC 边界。比较同输入结果、原始接口数、模型往返和耗时，无可比证据不宣称性能收益。

本轮以 Agent 的 [evaluation.md](../../agents/security-operations-expert/evaluation.md) 中当前策略与应急验收 Case 为唯一用例来源：三个策略场景验收授权下发及真实结果，四个应急场景分别严格停在准备、指令预览或仅创建任务。具体目标和参数不在本文重复维护。设备缺少凭据、上游业务错误或只建不启能力缺失如实阻塞，不降低通过标准；提交不证明设备已生效，生效不证明端到端连通。历史 Run、发布快照和其他版本不改写。
