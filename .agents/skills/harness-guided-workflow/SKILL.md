# Harness 引导式工作流

保持平台管理身份。有固定目标先用 `platform_agents` 的 `detail` 读取；缺目标时才查 `context` 或 `list`。需要方法时读取 `research/read-reference {topic:"controlled-improvement"}`，不先遍历历史或进入程序研发。

## 明确最小任务

先判断是新建、迁移、修改、优化还是多来源融合。核对用户所选 Agent、Experiment、失败 Run 及当前能力，不按最新编号选择父版。已有信息先查后问；只集中询问会改变目标、输入、预期行为、工具权限或资源限制的缺口。反问和方向讨论不自动构成实施授权，已有明确实施授权也不重复询问。

先确定一个高价值业务场景的可观察结果、不能退步的行为和停止条件，再确定固定来源、修改范围与最小比较。缺来源或必要权限时只暂停依赖它的操作；信息齐全且已有授权就进入下列对应技能，不强制每阶段重新提问或新增台账。

## 选择真实执行路径

- 新建：由 `agent-maintenance` 使用 `new` 创建真实角色和业务 Case；任务包含装配、限额修复及实例交付时使用 `task-builder`。
- 迁移：先用 `legacy-asset-intake` 清点来源，说明保留、适配和舍弃项；当前清点接口不自动导入或激活归档。
- 修改或优化：用 `harness-evolution` 固定父版并创建独立 Experiment。没有可比证据时可提出假设，不声称优化已成立。
- 多来源融合：用 `harness-experiment-fusion` 固定主来源、并行能力、冲突取舍及验证。已证实的算力终端版本可按其证据排除；仅有低算力名称不能排除。
- 评估：用 `research-eval` 对照固定输入核验实际观察、回归和替代解释，再按既有研究流程保存 Decision。

选择一条与用户目标匹配的主要路径；已有对应技能就从当前步骤继续，不因为技能互相引用而来回加载。旧资产清点完成后才决定是否迁移；创建、融合和评测均以返回的实际 ID 接续，不重新选择“最新”版本。

资产和运行均通过当前作用域提供的平台工具办理。创建、预览或保存只证明相应操作完成；改动需要新进程或新 Session 的实际装载与业务验证。平台工具缺口报告具体阻塞，不转入源码开发或执行导入资料。最终事实写回现有 Agent、Experiment 和 Run。
