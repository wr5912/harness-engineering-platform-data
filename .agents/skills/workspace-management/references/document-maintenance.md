# 数据工作区资料体检与整理

按工作区 [AGENTS.md](../../../../AGENTS.md) 判断归属、唯一来源和保留边界。此方法用于当前说明与索引；Case、版本资产和冻结记录使用其专用维护入口。

1. 固定用户指定范围和目标。通过平台上下文定位数据根，再调用 `platform_agents` 的 `documents/inspect {path}`。只读体检到此保持只读，不创建整理操作；只要求方案时交付方案。
2. 从所属入口阅读候选资料与工具返回的直接引用。将发现区分为有充分证据可处理、仍需判断和受保护；无静态引用、同名、时间久不构成删除依据。跳过项、动态配置、代码消费者和语义重复仍需按需核对，不把结构扫描称为完整审查。
3. 有整理授权且证据充分时，迁移有效的独有内容，修订所属入口和直接引用。调用 `documents/prepare`，传入明确的 `changes`；每项用读取的当前 `expected_sha256`，新建为 `null`。`update` 提供完整 `content`，`move` 提供 `to`，需要修订相对链接时一并提供移动后的 `content`；`delete` 仅针对已确认失效的当前说明。
4. 核对预览的范围、内容和引用。沿用已有授权与 DSH 原生权限，用返回的 `apply_input` 调用 `documents/apply`，不另设平台二次确认。摘要或引用冲突时重新读取并准备，不覆盖并行修改。
5. 回读涉及的入口和结果。回执丢失或状态未知先用原 `operation_id` 调用 `documents/status`，不重放。需要撤回时用原 ID 与 `expected_plan_sha256` 调用 `documents/recover`；后续已被修改的文件不会被覆盖，报告冲突并保留现场。

预览的原文和摘要只保存在本次工作区 `.local/document-operations/`，用于查询和恢复，不是新的知识来源。恢复仅覆盖该操作涉及的文件，不保证清除新建的空目录。普通整理不读取凭据或 HOME，不编辑 `evaluation.md`、Decision、Observations、Candidate、Run 与原始证据。

结束时说明实际改变、入口及尚未核对的消费者。体检、预览、写入、回读与业务验证分别报告；动态消费者不能确认时暂停相关删除，继续可独立完成的项。
