# 评测用例审查与优化

版本：V0.6
作者：luopeng
日期：2026-11-06

## 先确定任务和材料

先区分起草、只读审查、授权修改和授权精简；只读审查不保存、不执行业务。固定 Agent、当前文件摘要和用户范围，读原用例与总则，再按[方法依据](references/sources-and-methods.md)选必要材料。优先核对真实用户请求、实际附件、失败记录及业务需求；标明改编或构造条件。实现代码和历史回答帮助调查，不能自己成为正确答案。

用原材料回答：用户当时知道什么、想完成什么、愿意授权到哪里，以及用什么独立证据判定完成。不把评审者才知道的内部 ID、设备地址、表格内容、工具名、答案或内部步骤塞给用户。用户确实知道目标和业务参数时保留直接办理路径；不得为显得自然强制所有任务先查目录。

普通改写保留合规 ID、fast、真实输入及有效业务要求。用户明确授权精简或重选快速集时，可以合并、删除和调整档位，先核对独有要求及直接引用；历史 Run 保持冻结。改号另按[编号合同](references/platform-adapter.md#用例编号与授权改号)，不把删减后的空号回填或重新编号。

## 先审整套，再写单条

新建也先查看所属场景现有用例；完整审查不能只看本节中的入口覆盖或编号。

1. **任务与入口。** 从用户实际知道的信息开始，按业务需要保留咨询、发现候选、选定对象、继续办理，以及已知目标直接办理的路径。候选必须来自真实查询，说明时间、范围和分页；不能默选首条、猜 ID 或反复索取已取得的信息。
2. **区分力与必要性。** 对照用户目标、关键转折、业务风险和可观察结果，找出每例新增了什么独有验证。同义改写、换一个固定 IP、只换异常码或拆出内部步骤不能单独证明需要新增。能在同一目标的自然对话中验证的内容可合并；不能把无关目标串成超长用例来凑数量。
3. **保留、合并或移出。** 保留必要的正向闭环及有区分力的边界。固定 Mock 响应、字段/数值边界、解析、插件挂载等交给已有工程测试，核对实际文件和断言；存在覆盖缺口时明确记录或补对应测试，不能凭有测试文件就称已覆盖。需要模型理解或用户交互的业务判断仍留业务用例。失去保留价值的当前用例在授权内删除，不另建可编辑扩展库或归档副本。
4. **成本与执行能力。** 看实际轮次、等待、报告、外部写入、评审及历史耗时，选择能回答当前变化的最小相关集。fast 标记只是选择，不降低标准；阶段完整验收与日常定向验证分开。条数减少不能直接推算耗时收益。附件、分支条件、真实到期、浏览器和声音等前置要能准备并取证；执行器只会顺序发固定输入时，不能冒称已做根据回复选择的交互。

精简授权只允许减少冗余，不允许掩盖失败、删除尚未解决的有效业务要求或调低标准。已知唯一要求无法容纳时说明取舍及未覆盖范围。用例内容仍只在 Agent 的 evaluation.md 维护，研究方法及历史冻结记录保持各自来源。

## 写成可执行、可判定的用例

默认使用[用例模板](assets/case-template.md)，结构为：**标题 + 可选评估档位 + 用户输入 + 预期**。普通改写只交付正文；只读审查简要给出问题、证据、必要改法和限制。用户要求整套精简时说明核心选择及未覆盖范围，不额外创建评分表或评测平台。

- 标题用一个符合[编号合同](references/platform-adapter.md#用例编号与授权改号)的 ID 与业务名称，不夹带第二套编号。fast 放在标题后第一非空行；新建按本次测试目标决定，不写 full 标记。
- 输入是用户实际会说的话。多轮表示同一目标的真实交互，不将助手内部工具步骤拆成用户命令；不预填用户未知的候选或附件答案。实际已知地址和参数可保留，但执行前须核实，不能把示例当成真实资产。
- 预期按必要的主要流程说明动作和可观察结果，简单内容用一段即可。必要约束就近写清；区分准备、提交、执行、效果与产物可用，不用“正确、完整、合理”代替判定。
- 有证据的候选、序号、数量和状态以本轮实际结果核对，允许等效实现与表达。不绑定内部模型、MCP 连接名、私有字段或固定 UI；必要业务接口和字段须有实际合同依据。
- 只读、取消、等待确认与明确执行按用户停点办理；同一请求回执未知先查询，不自动重放。缺页、空结果、读取失败、未执行与结果未知分别判定，不把失败说成没有问题。
- 正向例须有真实成功回执和要求的产物，不能把说明缺口改成通过。负向例须有实际分支条件及完整观察；无候选不能证明候选消歧正确，没运行也不能证明重复写入被避免。缺日志不能证明没有操作。
- 固定口径与执行观察分开。预期不能抄目标回答当答案；自动评审、完成状态或表述流畅不能抵消事实错误、必要产物缺失或写入越界。

参考[示例](assets/u-ins-001.platform.md)核对自然入口和单例粒度，依照[平台格式及执行限制](references/platform-adapter.md)保存和执行；不新增自定义变量或参数化语法。

## 交付前反查与写入交接

核对整套的真实入口、独有价值、核心闭环、成本及执行前置；再逐条核对编号、场景缩写、输入、fast、可判定预期、产物和有效限制。用“错误数量、重复启动、缺报告却声称完成”等反例检查判定能否拒绝错误；关键事实需有独立证据，不能让同一模型自述替代结果。

接收 agent-maintenance 固定的目标、增改/精简删除/改号/排序范围与当前摘要，按[平台适配合同](references/platform-adapter.md)预览、写入并回读。新建前先比较现有用例，删除前核对独有要求及当前直接引用。仅排序提交完整 ID 顺序，不改正文；摘要冲突重读并保留并行变更，回执未知先查结果。没有授权只返回建议，不保存或执行。
