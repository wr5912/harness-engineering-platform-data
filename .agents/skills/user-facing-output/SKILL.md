# 面向用户的表达

先回答用户关心的结果、影响和必要行动。交代清楚即可结束；用户要求明细、完整报告或论证时充分展开。不要让用户先解读状态码、数据结构或内部流程才知道结论。

## 先判断产物给谁使用

| 产物 | 默认交付方式 |
|---|---|
| 决策模型的训练、开发、校准、测试数据 | 严格遵守数据合同，保留 JSONL、协议字段、枚举和真实值；不向数据行插入说明、Markdown、注释或为了好读而改写输入。另附面向人的数据说明。 |
| 方案、决策点清单、数据审查、复核说明、训练准备及运行结果 | 优先中文短段落或 Markdown 报告；比较用表格，步骤用有顺序的清单。默认不以 JSON/YAML 对象或完整日志作为唯一答复。 |
| 工具参数、程序状态、配置、命令和可执行文件 | 保持接口要求的机器格式；程序记录保留，用户先看到结果说明。用户明确索取原始格式时原样提供。 |

面向人和面向程序的文件使用同一组事实。报告中的数量、状态、失败和下一步都来自实际结果；不能为了语气顺畅，省略阻止继续的条件。机器报告存在不等于用户已经得到说明，生成可读报告也不等于数据或业务已经通过。

## 写清结果和依据

- 基本用法咨询先说明能得到什么、最短起步方式和必要输入。Skill、研究方法和检查清单指导执行，不逐项转述成回复模板。
- 用具体业务动作和结果组织内容，不加自我过程宣告或所用 Skill、工具调用的开场说明。进展只补充新信息；保留影响判断的失败、未知、尚未保存和待复核状态，不以“已完成”掩盖缺口。
- 生成结构化产物时，题干、选项说明、解释、判断依据等人类可读值优先使用中文，或用户明确要求的语言。字段名、协议枚举、工具动作、ID、路径和原始证据保持原样；不为翻译增加合同外字段，也不批量改写已有数据。
- 只呈现当前判断需要的证据。完整 ID、摘要、分页和日志留在可查看记录中，排障、区分对象或用户要求时再展开。只给已核实的平台入口或真实 URL；相对路径、本机路径不能自动当网站链接，没有可访问地址时说明页面名称和操作位置。
- 需要原生权限批准或业务确认时，先说明动作、对象、预期结果及重要额度或影响；沿用已有授权，不另设平台确认。用户暂不执行就说明未执行或未保存的部分，不重复提出同一确认。
- 使用连贯短段落；并列事项用清单，比较用表格。先解释必要术语的用途及问题影响，再给技术定位；不机械逐字段汇报，不用固定字数或禁词清单判断质量。完成且无必要操作时不追加下一步。
- 分开说明保存、格式检查、标签复核、编码检查、训练、装载和业务效果。命令生成不等于训练完成，工具调用成功不等于业务通过，已有复核也不自动证明完整任务效果。

需要数据、训练、研判失败或基本用法的表达示例时，按需读取[场景示例](references/scenario-examples.md)。示例不提供本次真实结果或额外权限。
