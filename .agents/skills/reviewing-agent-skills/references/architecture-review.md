# 执行主体、技能集合与控制流审查

本页是 `local-quality` 架构审查协议，按任务范围启用；不是 Agent Skills 官方格式的新增硬约束。相关官方设计建议标为 `official-guidance`，产品行为则须按目标运行时与版本核实。规则来源沿用 [来源说明](sources.md)，发现分级与证据结构沿用 [审查量表](review-rubric.md)。

仅审查一个简单 Skill 时，检查其直接相关的执行者、相邻入口和依赖即可；不要求全仓盘点、绘图或新增子智能体。用户要求集合审查、能力分工，或发现跨 Skill/Agent 交接时，再展开对应专项。缺少集合清单时，不能宣称整个集合无冲突。

## 1. 输入与证据范围

先记录审查对象、固定版本、运行时、代表性任务和用户约束；只索取会改变结论的缺失资料。按本次专项读取：

| 输入 | 可证明什么 | 不可据此推断什么 |
|---|---|---|
| Skill 入口、引用、脚本及调用说明 | 声明职责、知识依赖与预期步骤 | 已实际加载或完成任务 |
| Agent 定义、装载配置和目标工具合同 | 声明执行者、可见范围及配置意图 | 子智能体必然继承主智能体的上下文、工具或 Skill |
| 实际发现/加载回执、上下文快照 | 对应实例与时点的可见、预载或读取状态 | 所有实例或以后会话都相同 |
| 任务样本、失败记录、真实 Trace | 被观察请求的路由、执行及结果 | 未观测路径也成功，或低频能力无价值 |

区分资产版本、运行时版本和任务运行版本。无法访问实例时继续静态审查，将实际可见性、交接效果和成本标为未验证，不猜造工具、配置字段或运行结果。

## 2. 执行主体与 Skill 搭配

### 输入与判断单位

以能说明目标、输入和验收结果的能力为单位，结合任务样本、现有执行者及工具权限。Skill 是可复用的知识与操作指引；Agent 是执行主体，两者不是互斥选项。一个 Agent 可以使用多个 Skill，同一 Skill 可以被多个 Agent 使用。

### 逐步检查

1. **列出实际能力。** 写明完成什么任务、当前由谁判断和执行、哪里失败或重复；不按文档章节机械生成子任务。
2. **选择执行边界。** 用下表比较主智能体、子智能体和确定性工具，说明为何保留当前方案或调整；不把“步骤多”直接等同于需要委派。

| 观察到的条件 | 优先考察的方案 | 必须核对的取舍 |
|---|---|---|
| 任务短、频繁依赖用户交流，或阶段共享大量上下文 | 主智能体执行，按需使用 Skill | 是否值得承担交接与重复读取成本 |
| 子任务可独立验收，需隔离大量探索上下文，或能独立并行 | 子智能体执行，按需配 Skill | 输入能否完整传递、结果能否汇总、隔离与并行是否真实存在 |
| 知识或操作约定稳定复用，但不需要独立执行上下文 | 复用或完善 Skill | 不因知识复用单独创建 Agent |
| 操作确定、接口稳定、无需新业务判断 | 脚本、复合工具或工作流 | 采用 [MCP 编排边界](mcp-boundaries.md) 核对失败语义与运行条件 |
| 长期状态、事务或跨阶段副作用需要可靠管理 | 现有应用工作流/状态机 | Skill 或子智能体文本能否承担该保证；缺口不自动授权新建服务 |

3. **确定 Skill 搭配。** 优先复用已有能力。多个 Skill 配给同一子智能体时，说明它们怎样共同完成一个可独立验收的任务，并核对共享上下文、工具/数据范围、授权与产物责任是否兼容；仅术语或领域相似不足以支持打包。能够独立并行、需要独立评审或权限边界不同的任务，分别评估执行边界。只有稳定、可复用且独立维护有价值时，才建议新 Skill；不要求每个子任务创建一个 Skill，也不把每个 Skill 固定绑定一个 Agent。
4. **核验执行条件。** 逐执行者核对模型/上下文限制、工具、权限、资源版本、Skill 的发现或预载方式及实际装载证据。主智能体能读到文件不证明子智能体可读；读取 Skill 本身不等于创建了子智能体。
5. **检查交接合同。** 委派应携带目标、必要上下文与来源、输入版本、权限边界、预期产出和停止条件；回传应区分结果、证据、已完成动作、未决状态和失败。确定谁验证、解决冲突并汇总最终结果，避免无人负责或重复验收。
6. **检查状态所有权。** 明确谁持有任务状态、谁可提交外部写入、谁处理重试/取消/恢复；并发修改同一对象时核对实际版本或冲突机制。委派不扩大原授权，也不默认需要新增审批。
7. **核对未知副作用。** 写动作超时或回执丢失时，先按现有任务标识/对象状态回读，再决定续作、补偿或停止；不得由另一个 Agent 盲目重放。取消执行也不自动证明外部动作已撤销。

### 最小输出

| 能力与代表任务 | 当前/建议执行者 | 所需 Skill 与实际可用证据 | 输入/回传与状态负责人 | 裁决、取舍及验收 |
|---|---|---|---|---|
| `<实际能力>` | `<主/子 Agent、工具或组合>` | `<可多选或无需 Skill>` | `<交接与副作用边界>` | `<保留或最小调整>` |

**证据不足边界：** 仅有定义时可评价分工意图，不能判定实际隔离、权限继承、并行收益或子智能体装载成功。缺少明确交接是静态缺项；其失败频率和成本仍需轨迹验证。

## 3. 集合规模与入口路由

### 输入与计数口径

读取本次范围内的目录清单、运行时发现/装载配置、相邻 Skill 描述及代表性任务。先分清四层，未知项单列，不把目录数量当作模型负担：

| 层次 | 记录内容 | 成本与风险观察 |
|---|---|---|
| 资产层 | 仓库/安装位置的包、版本、共享或嵌套资源 | 维护、重复资产、过期依赖；不等于全部被发现 |
| 可见入口层 | 当前执行者实际可见的名称/描述及用户、模型调用面 | 路由歧义、描述上下文与入口遗漏 |
| 按需加载层 | 本次请求实际读取的正文及引用 | 读取量、重复规则、无关上下文 |
| 子智能体预载层 | 各子智能体启动时实际注入的 Skill/规则 | 每次启动成本、冲突与不必要预载；区别于可发现但尚未读取 |

调用面和预载合同须按目标实现核对；不把 Claude Code 的 `skills`、`context: fork` 等字段或行为直接套到 DSH。预载、可访问、实际使用分别记录。

### 逐步检查

1. **界定集合。** 写清包含哪些包、执行者和调用面；去重时保留版本与来源差异，说明排除项。仅查一个子目录时不声称全量覆盖。
2. **从任务找入口。** 选核心、相邻、低频但关键、异常和明确不应触发的请求，标注预期主入口、合法辅助能力和无人承接项；实际调用面尚未知时保留两者的区别。
3. **审查竞争与组合。** 对重叠描述读取必要正文，判断是重复承担同一责任、合法顺序协作，还是共享规则。要求分流依据可判断；不能仅凭关键词相似或同时触发就判冲突。
4. **判断过多的证据。** 查找持续误触发、只转发而没有独立价值的入口、相同规则多处漂移，以及过高的可见/预载成本；分别考虑收窄触发、引用公共规则、按需加载或合并。
5. **判断过少的证据。** 查找一个入口承担互不相关的目标、分支难以选择、独立权限/生命周期混在一起，以及关键任务无路可走；比较补分流、拆出参考资料、独立 Skill 或更换执行主体。
6. **保留有价值的低频能力。** 恢复、异常处理、审计等能力不能仅因使用少被删除。没有任务分布时，少调用也可能是未被发现；应先核对入口和业务价值。
7. **验证数量调整。** 不设通用“最佳 Skill 数”或硬删除阈值；按任务覆盖、路由准确性、上下文与维护成本检验候选集合。只有资产计数时，只报告规模，不判定过多/过少。

### 最小输出

| 任务域/样例 | 预期主入口与辅助 Skill | 实际路由或未验证 | 缺口/争抢/合理重叠 | 最小调整与回归 |
|---|---|---|---|---|
| `<任务>` | `<允许多个协作入口>` | `<回执或 NOT_RUN>` | `<定位及机制>` | `<保留/调整>` |

同时报告四层的已知数量或范围、未知层及适用执行者。**证据不足边界：** 没有邻近 Skill 内容，只能标潜在冲突；没有完整清单或任务样本，不能证明集合完备、最优数量或低频能力可废弃。

## 4. 依赖、控制流与实际轨迹

### 输入与三类关系

从入口、必要引用、执行者定义、工具合同和已有 Trace 提取关系；每条关系标明类型、来源、版本和观察范围。可用短表，无需强制画图。

| 关系 | 表示什么 | 证据边界 |
|---|---|---|
| 依赖/引用 | 读取说明、复用规则、需要资源或工具 | reference 互引不自动构成执行环 |
| 声明控制流 | 指令中的分支、调用、委派、等待、重试、恢复和结束 | 可发现矛盾或不可达分支，不能证明实际走过 |
| 实际执行轨迹 | 某次运行的调用、并行、交接、状态与结果 | 只证明观察过的路径；调用缺失也可能源于采集不完整 |

### 逐步检查

1. **选取相关路径。** 从代表任务的入口到完成或失败停止，标出决策者、执行者、输入/产出、前后依赖和状态负责人；简单单 Skill 以一行说明即可。
2. **区分控制动作。** 读取文件、应用 Skill 指引、创建/恢复子智能体、调用工具、回收结果分别记录；静态链接不计作一次运行调用。
3. **寻找复杂性的实际机制。** 检查深层转交、过大扇出、反复做同一决定、分支入口重叠、结果无人汇总、共享写状态冲突和不必要串行。长度、步骤数或图中有环本身不是缺陷。
4. **检查循环与停止。** 对重试、评估改进、回访等合法循环，核对进入/退出条件、进展证据、任务适用的次数/时间/成本边界、取消传播和无进展处理。数值上限来自用户、目标合同或经说明的具体风险，不给所有任务新增统一额度；可判断的完成、阻塞与无进展出口也可构成有效边界。可停止且有价值的循环不应为消除图环而删除；无界或停止信号失效须指出定位。
5. **核验恢复路径。** 对失败、结果未知、部分完成、取消和重新开始，检查状态如何回读、未完成子任务如何处理，以及谁决定安全重试或补偿；复用第 2 节的交接与副作用检查。
6. **选择最小结构调整。** 依下表比较保留、简化、合并、拆分、委派与下沉，区分文档组织变化和执行边界变化。

| 候选调整 | 支持它的证据 | 应保留的边界 |
|---|---|---|
| 简化或移到参考资料 | 同一任务的细节掩盖入口，或重复维护公共规则 | 不因此增加新的执行主体或路由入口 |
| 合并 Skill/入口 | 核心任务和生命周期相同，重复触发/规则漂移已有依据 | 不吞并独立权限、独立验收或有价值的异常入口 |
| 拆分 Skill | 存在可清楚分流、独立复用/维护的能力 | 仅在需要时保留导航，不为每个独立入口新增转发层 |
| 委派子智能体 | 独立子任务与上下文隔离/并行有价值 | 满足第 2 节，计算交接与汇总成本 |
| 下沉脚本/工具/工作流 | 固定且确定的步骤重复消耗模型判断 | 保留必要策略、异常处理、可观测性与授权边界 |
| 保留现状 | 分支有业务意义、边界清楚，调整收益不足 | 记录理由；允许不整改 |

7. **用轨迹核对假设。** 查声明路径是否真的重复执行、瓶颈在模型轮次还是工具内部、并行是否缩短关键路径；没有 Trace 时只给静态结构结论与实验假设。

建议工作流时明确哪些条件和操作由代码控制、哪些仍依赖模型。产品中名为 `workflow` 的工具可能仍会启动智能体，不能仅凭名称称其输出确定或已减少模型参与。

### 最小输出

| 路径/边与类型 | 来源或 Trace | 决策/状态负责人 | 复杂性与失败机制 | 裁决、取舍及验收 |
|---|---|---|---|---|
| `<依赖/声明/实际>` | `<文件行号或运行标识>` | `<实际责任>` | `<确证或假设>` | `<最小调整>` |

**证据不足边界：** 静态控制图不是执行 Trace；有调用记录但缺耗时、Token 或结果时，不补造性能值。没有恢复回执，不把“规定先回读”写成恢复已成功。

## 5. 最小交付与收益验证

对三个专项分别给“通过 / 不符合 / 不适用 / 未验证”，说明范围、定位或原因；可直接把本页三张最小输出表纳入 [报告模板](../assets/review-report-template.md)。简单目标可用等价短段落，不强制填空表或补全仓图。

按 [评估指南](evaluation-guide.md) 比较原方案与最小候选方案，必要时加入不加载 Skill 或不委派的基线。保持任务、模型配置、工具权限和资源版本可比；架构变更必须记录实际改变的因素。

- **分工：** 观察必要上下文/Skill/工具是否到位，交接与汇总是否完整；失败或取消后能否识别真实状态，避免重复副作用。
- **路由：** 检验正例、改写、相邻、竞争、无人承接和低频关键任务；记录预期主入口与允许协作集合，不能把合法多 Skill 协作计为误触发。
- **控制流：** 检验正常、分支、失败、结果未知、取消及循环退出；合并或拆分后重跑受影响入口与恢复路径。
- **收益：** 先比任务成功率与结果可靠性，再看端到端延迟、全部主/子 Agent 的模型轮次与 Token/成功任务、工具调用、重试、交接和重复读取。主 Agent Token 降低不证明系统总成本降低。

只运行能区分候选方案和真实风险的案例，尊重授权与资源上限。无可比轨迹时保留收益假设、验收方法和 `NOT_RUN`；不得报告已经省时、省 Token 或更可靠。验收完成后停止，不扩充无关治理设施。

## 6. 官方参考的使用边界

以下资料核对日期为 2026-10-29；复审其他版本时重核相关条款。本页表格和判断步骤是本包的 `local-quality` 协议，不是下列资料逐字规定的官方验收门槛。

- [Agent Skills Specification](https://agentskills.io/specification)：格式与渐进披露；格式判定仍使用 [固定来源](sources.md)。不从其组织建议推导主/子 Agent 数量或一对一配 Skill 的硬要求。
- [Anthropic: Building effective agents](https://www.anthropic.com/research/building-effective-agents)：简单方案优先、路由、并行与编排的 `official-guidance`；文章中的设计取舍不是所有运行时的强制实现。
- [Claude Code subagents](https://code.claude.com/docs/en/sub-agents)：独立上下文、主/子任务选择及 Skill 预载的产品资料；仅能证明相应版本的 Claude Code 行为，不能证明 DSH 支持相同字段、继承规则或限制。

目标运行时的发现、装载、委派、权限及恢复合同应取自已核实的对应版本；资料与实际回执不一致时保留双方证据，收窄结论。
