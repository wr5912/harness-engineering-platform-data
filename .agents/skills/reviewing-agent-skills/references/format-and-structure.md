# 官方格式、内容与工整性检查表

## 适用范围与证据

每个目标都完成本表的适用项，并在报告中记录“通过 / 不符合 / 不适用 / 未验证”及文件定位。没有定位或实测结果时不能记为通过；“不适用”须说明任务类型与原因。复核日期：2026-10-28；固定来源及版本见 [sources.md](sources.md)。

规则来源分四类：`official-spec`（官方规范条款）、`official-reference`（固定参考实现策略）、`target-runtime`（已核实的目标合同）、`local-quality`（本审查技能的内容与工整性要求）。官方组织建议单列 `official-guidance`，逐项判断采用或有理由偏离，不伪称明文硬要求。

## 1. 官方格式与参考实现

| 项目 | 必须核对的内容 | 来源与判断 |
|---|---|---|
| 目录与入口 | 通用目录包至少有准确命名的 `SKILL.md`；内容为 YAML frontmatter 后接 Markdown 指令 | `official-spec`；脚本、参考和资产目录可选，不要求空目录 |
| YAML | frontmatter 正确闭合，能解析为映射；键唯一，不默默用后值覆盖前值 | 官方格式与 YAML 规范；记录解析器，不能用字段正则代替完整解析 |
| `name` | 非空，1–64 字符，小写字母数字和连字符；无首尾/连续连字符；与目录名匹配 | `official-spec`；官方参考接受 Unicode 字母数字并作 NFKC 归一；不要把 DSH 的 ASCII 限制泛化 |
| `description` | 非空字符串，1–1024 字符；另外人工判断是否说清用途与触发情境 | 长度/存在是格式检查，内容充分性另记语义结果 |
| `license` | 可选；如有，说明许可证名称或随包许可证引用，类型与内容有效 | `official-spec`；不要求所有 Skill 新增许可证字段 |
| `compatibility` | 可选；提供时为 1–500 字符，写真实环境要求 | `official-spec`；空值不是“字段可选”的等价表达 |
| `metadata` | 可选；字符串键到字符串值的映射，不用数组或嵌套结构冒充 | `official-spec`；官方 StrictYAML 将普通标量解析为字符串，`version: 1.0` 不自动违规 |
| `allowed-tools` | 可选；空格分隔的工具字符串，不能把数组当字符串；支持情况按运行时核实 | `official-spec`；实验性字段不等于运行时已经执行了权限控制 |
| 其他顶层字段 | 通用参考工具只接受六个已列字段；额外字段先核对目标扩展 | 拒绝未知字段属于 `official-reference` 策略，不冒称规范正文逐字要求拒绝所有扩展 |
| 实际引用 | 文件与路径存在，内容和读取条件相符；链接、锚点、大小写及跨包依赖逐项核实 | 路径组织是官方建议；实际缺失或错误引用影响执行，不能因检查器没覆盖而判通过 |

字段可选不等于字段出现时可以忽略其约束。规范与参考实现行为不一致时保留双方来源和原始结果，不擅自选一个结果宣称全部合规。当前官方 `skills-ref` 不覆盖所有可选字段与正文质量，成功回执只证明其已实现检查通过。

## 2. 目标运行时单独核对

DSH `0.2.1-rc.2` 的固定来源为 `687f282e8625c6b8d11ff58211a90524be2e4317`：

- 名称采用 ASCII kebab-case，比通用参考的 Unicode 名称范围窄；格式符合通用标准不等于 DSH 可加载。
- frontmatter 的开始、结束行须在去除 CR 后准确为 `---`；该版本不接受分隔符尾空白或文件首 BOM。通用解析器接受这些写法不能证明该 DSH 版本可识别。
- 支持 `whenToUse`、`metadata`、`disable-model-invocation` 和 `user-invocable`。调用开关支持布尔值以及该版本明确接受的 `true/false`、`yes/no`、`on/off`、`1/0` 表示；原生解析与实际调用面仍单独验证。
- `disableModelInvocation`、`modelInvocable`、`userInvocable` 是该版本拒绝的旧字段。不能把旧字段无效解释成当前规范没有调用控制能力。
- 目录包、扫描根的扁平 Markdown、嵌套上游参考包是不同形态。本包静态命令只检查显式传入的目录包，不用其目录假设判定其他原生形态违规。
- 合法 DSH 扩展可以被通用参考工具拒绝；报告“目标支持的扩展”和“通用可移植性限制”，不为消除提示删除调用控制或改写官方原文。
- 本包与官方参考都使用 StrictYAML 的受限解析能力。某种 YAML 表示不被参考解析器支持，不证明 DSH 的原生 YAML 解析失败；这类表示转交目标解析器，不能伪造原生通过或失败。
- StrictYAML 的字符串标量语义不能替代 DSH 原生类型推断。名称、描述、`whenToUse` 的数字/布尔式标量，以及可能成为数字 `0/1` 的调用开关表示，若无法确定原生类型则记为受阻并交原生解析核验；必要时包括合法但本检查器无法消除歧义的引号写法。受阻表示证据不足，不表示目标配置违规。

## 3. 正文内容：检查信息充分性

官方没有固定标题、章节数量或顺序要求。下面是本地严格内容审查表，允许等价标题、短正文和明确引用公共规则；不得只数标题或靠关键词打勾。

| 内容项 | 每部分应怎样写、怎样判断 | 适用性 |
|---|---|---|
| 用途与分流 | 说明具体解决什么问题、何时触发；相邻任务由谁承接；description 与正文职责一致 | 所有类型 |
| 输入与前置条件 | 说明必需对象、信息来源、工具/环境；缺失条件如何补齐，哪些不阻塞后续 | 过程与工具类重点；参考/表达类说明适用对象 |
| 方法与分支 | 写清条件、动作、观察结果；分支条件可判断，步骤顺序与依赖一致，不用“妥善处理”代替方法 | 过程类给流程；表达/参考类给可应用规则或导航 |
| 产出与完成 | 说明产物、结果依据和完成条件；保存、校验、装载、业务结果分别取证 | 所有类型，粒度随任务调整 |
| 失败与停止 | 有状态/副作用任务说明失败、结果未知、重试、回读、取消与恢复；不盲目重放写动作 | 无副作用的表达/参考类可说明不适用 |
| 依赖与引用 | 指向真实工具合同、来源、版本和参考；说明何时读取，不依赖读者猜测隐藏前置条件 | 存在依赖时 |
| 示例与边界 | 示例应展示容易误解的格式或分支，并与正文、工具 schema 一致；复杂或高误用流程有反例/边界 | 简单规则可由简短说明充分表达，写明理由 |

空章节、仅有标题、模板式口号或一句“执行任务”不能证明具备方法。只读表达规范不需要硬凑训练、部署、回滚章节；官方参考包的补充接入说明放在本地适配入口。

## 4. 工整性：逐项人工核对

| 项目 | 通过依据 |
|---|---|
| 标题与顺序 | 能看清任务结构，标题准确、层级和顺序有意义；无标题短文仍可合格。疑似跳级或空章节需要结合语义判断 |
| 段落与列表 | 每段表达一个清楚目的；并列项同一层次，步骤编号与依赖一致，不重复堆叠同义要求 |
| 术语与规范词 | 同一对象名称、字段和状态一致；必须/建议/可选有来源，条件和例外就近说明 |
| 表格与代码 | 表头/列值对应，命令、代码块、缩进和围栏表达清楚；检查疑似截断、占位残留与格式混淆 |
| 链接与示例 | 相对路径和锚点有效；示例属于真实可用、示意还是待填写模板有明确标注 |
| 简洁与渐进披露 | 主文只保留任务必需规则，细节按需引用，避免正文/参考重复维护；长参考提供可浏览结构 |

上述是 `local-quality` 审查要求，不是新增官方标题语法。Markdown 允许的简写或未闭合围栏并不自动构成官方格式错误，但若造成指令混淆仍需报告实际质量问题。正文约 500 行、较浅的引用链与长参考目录属于官方写作建议，应评价理由与实际可读性，不自动判为加载失败。

## 5. 验证与结论边界

- **官方条款核对**：逐条保留来源和证据，包含参考工具未覆盖的字段与内容边界。
- **官方参考验证**：记录实际执行的 `skills-ref validate` 版本/命令/回执；未执行填未验证。
- **本包静态检查**：完整记录错误、依赖阻塞、启发线索和覆盖边界；`metadata=PASS` 只代表该检查器的元数据范围。
- **人工内容与工整性**：分别逐项记录正文/参考定位，不能用静态空结果代替。
- **原生与行为验证**：加载/调用/任务结果分别取证。检查器单测或合成样例不能冒充全部目标技能验收。

只有适用项均有证据且无不符合/关键未验证，才可在明确范围内给通过结论。运行轨迹不在本次范围时可以给“静态审查通过，运行行为未验证”，不得缩写成“全部通过”。
