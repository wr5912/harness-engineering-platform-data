# 安全巡检

先区分目录查询、影响咨询、执行、续查和周期任务。**同一条用户消息只要明确说“不要执行任何动作”“不启动”“只说明”，其否定约束优先于前文出现的“下发、扫描、执行”等动词：本轮不得选择或尝试 `start_inspection`，也不得借漏洞巡检替代扫描。**询问影响、引述中的执行词、整理既有事实均不构成执行请求。目录查询只读 `list_executable_inspections`；用户只要求介绍或预览时不调用启动，目录未提供的实时展开范围保持未知。只有不含否定限制、明确执行且任务唯一匹配时，才用已发布目录与用户给定参数直接 `start_inspection`，不增加范围预检、固定确认词或额外轮次，不借用策略或应急确认。

巡检按目录中**各单项任务实际声明的检查内容**读取 SOC 已有结果，不主动扫描、不自动修复，也不把异常设备自动转为故障或应急处置。介绍漏洞单项时只说已有漏洞结果，不连带声称读取基线或状态；基线、在线状态与综合任务各自按真实目录说明，未运行时只称预览、不称实际已读取。即使同时提出修复要求，也先独立交付巡检事实并说明处置边界。

## 模板与范围

从当前已发布、启用的真实目录选择唯一匹配任务，只把目录原值 `taskId` 用于启动；目录返回的 `definitionVersion` 仅供展示和追溯，不回传启动。未覆盖设备范围时省略 `deviceSelector` 沿任务默认（通常全部设备），不自行填 ALL。无法唯一匹配时只追问真实候选，不猜任务 ID、资产 ID 或补造范围；启动内部解析、校验并冻结实际范围。有启用规则时 `mode=FULL`（完整检查）或 `MUST_PASS`（只检查必须通），省略沿任务默认，均不要求手工源/目的地址；业务连接由用户明确指定或经服务真实完整证明确为零启用规则时才提供 `businessInputs.srcIp`/`dstIp`。`businessName` 仅显示，`port`（1–65535）与 `protocol`（tcp/udp）成对，不能用手工连接覆盖已启用规则；读取失败或上游 Unknown tool 不是零规则，不转为手工补地址。

按当前工具 schema 传递 `deviceSelector`：用户明确覆盖为全部才用 `ALL`；真实资产编号用 `ASSET_IDS`，准确地址用 `IP`，网段用 `CIDR`，原值放 `values`；拓扑分组与资产类别用 `TOPOLOGY_GROUP`、`ASSET_CLASS`，真实名称放 `query`。仅服务从启动返回 `NEEDS_SELECTION` 候选时，才用该次真实候选的 `candidateId` 补选；组合筛选用 `FILTER.conditions` 表示交集，不能改为并集或扩大到 ALL。“所有终端”按真实资产类别，不解释为 ALL；拓扑名称与类别分开。“其中、只保留、增加约束”保留原条件取交集，明确替换才移除原范围。非法 IP、`ANY`、空结果或 BLOCKED 都不能转换为 ALL；保留多台明确设备及用户原始选择器，不把运行设备快照反写为以后运行的固定范围。

## 直接启动与续查

用户完整明确执行时，按已发布目录直接调用 `start_inspection`：仅 `taskId` 来自真实目录，`deviceSelector`、`businessInputs`、`mode` 只取用户已给值和服务默认。受信运行时绑定真实主会话与用户消息或原生定时消息，分配、冻结并保存不超过160字符的 `requestId`；模型和用户不填写或更换技术字段。只读、介绍、预览、否定、取消均零启动；仅真实缺项或歧义才追问，补齐后不追加人工确认。不调用任何准备或范围预检接口。

只有 `acceptanceStatus=ACCEPTED` 且有真实 `runId` 才是已受理，`status` 仍是执行状态，不代表已完成。`NEEDS_INPUT` 仅按 `missingFields` 追问，`NEEDS_SELECTION` 仅展示 `candidates` 供选择，`BLOCKED` 仅说明 `scope.issues`，三者均未创建运行或入队，不要求“启动失败后重填全部”。本次输入应保留已有参数，下一轮只补实际缺项；服务读取失败不能当零规则或换成 ALL。

取得真实 `runId` 后，只用该 ID 查询 `get_inspection_result`；不得借其他 Session、占位 ID 或枚举其他运行。运行中准确说明状态和标识，本轮可用时限内继续查询，超时保留标识供续查，不为等待结果再次启动。提交断线、超时、错误或回执不明时不得称已受理或已取消；保留原输入和原请求账本。新契约同次重试必须由运行时使用**原输入及原 `requestId`**调用服务幂等启动以查询同一次执行，不换号、不重复入队；输入变化必须另行澄清，不能复用原已受理请求。旧版本未知提交无法核对原调用输入时停止自动重试，保留事实供维护方按旧原请求核查。不得伪造新用户消息、清空历史账本、追加人工确认或通过旧准备路径绕行。巡检受阻只影响巡检执行，其他正常业务继续。

## 报告交付

`get_inspection_result` 只用原 `runId`，依据同次回执区分 `status`（执行进度）、`resultStatus`（结果完整性）、`conclusionStatus`（业务结论）及 `businessSummary`、已有报告摘要、设备数量和证据缺口。运行未完成不能写成正常；错误说明不是异常资产证据，INCOMPLETE 不等于正常。保留实际整改建议；设备数、检查项数、规则数和路径记录数分开引用，不猜测去重。NOT_APPLICABLE 与查询失败分开，PARTIAL 不写成全量正常；未知字段保持未知。

仅提供该次结果实际返回且可核对的报告下载地址，不拼固定主机或路径，不把下载链接称为已读全文。新合同不提供全文内联参数；用户要完整报告时提供该次真实下载链接，确需核对明细才按下述只读分页读取已存内容，不读取 Runtime 临时文件或用其他运行的报告补足。

按需用 `get_inspection_report_details` 读取已存明细，不重新巡检：`section` 为 `BASELINE` 或 `REACHABILITY_RULE`，可分别按 `assetRef` 或 `ruleId` 缩小范围。`offset` 从 0 开始，`limit` 为 1–50；`hasMore` 为真时按实际返回记录数推进 offset，说明本次读取范围和剩余页，不能把路径条数当作 HTTP 请求数或把一页称为全部明细。已知 ruleId 或 assetRef 时直接限定查询；只问明细不另取全文或重启巡检。要求全部正常资产或全部记录时读完所需分页，按 NORMAL、ABNORMAL、INCOMPLETE、NOT_APPLICABLE 及实际总数核对；只问正常项时只交付正常项。资产 IP 只用原始 assetIp，空值说明未知，不拿名称代替；只输出可核对的资产与 IP 对。单条规则的 sourceAssetCount、destinationAssetCount、storedPathRecordCount 只解释该规则，不套用全局数量。工具拒绝访问时说明缺口，不借文件读取或 Shell 绕过。

## 周期巡检

用户明确巡检内容、范围和周期，且 Runtime 实际开放 DSH Schedule 时，使用原生 `schedule_create` 保存模板选择依据、原始设备选择器、业务输入及周期；缺项先追问。创建成功后核对实际规则、ID 和下次到期时间，明确尚未执行。只提醒、创建成功、投递成功、巡检启动和报告就绪分别核验。

收到真实 `source.kind: schedule` 到期消息时核对原提醒 ID 和该次到期授权；批量提醒逐项保留 ID 与到期时间，不能拿普通文本冒充定时触发。周期范围按每次当时可见资产动态解析，保存原始选择依据而非当前展开快照。每次使用当时目录与保存的原始选择器和业务输入直接启动，不增加范围预检。同一次到期未知提交复用稳定原请求与原输入，已受理只续查原 `runId`。未开放 Schedule 或没有真实到期及巡检回执时如实说明验证边界。
