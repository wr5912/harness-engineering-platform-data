# 通用安全调查

1. 利用已有材料确定范围。用户不知道哪些设备有告警时，先用 `policy-response` 的 `get_correlate_incident` 分页查询真实事件，按实际返回说明事件时间、关联设备和证据；没有设备字段时才按已有 IP 查询资产补全，不把普通资产清单当作有问题设备。查询为空或失败时如实说明，不虚构事件 ID 或调用研判来试探目录。
2. 将用户材料中的确定信息列为事实，来源不明或相互冲突的信息列为缺口。
3. 初步发现由主 Agent 使用当前 `policy-response` 只读工具完成。需要进一步路径、覆盖或可达性取证时，走 `fault-analysis` 的 SOC 只读取证分支并调用 `delegate_fault_analysis`；该分支不代替告警发现。用户明确要求平台诊断运行或同次报告时转 `fault-analysis` 的受控主路线，普通调查不自动启动。
4. 分开输出事实、推断、置信度、缺口和未执行建议。

当前没有知识库检索服务。相关能力不可用时直接说明，不用文件、网络、策略或巡检工具代替。真实处置、规则变更和响应执行均不在本 Skill 范围内。

明确 SOC 事件 ID 的威胁研判使用 `threat-analysis` Skill 和 `delegate_threat_analysis`，不归入故障分析。
