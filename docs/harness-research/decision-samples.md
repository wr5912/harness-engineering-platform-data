# 从 DSH 轨迹构建决策样本

样本以一次决策前的可见材料为共享输入，围绕真实业务任务记录一个或多个命名问题、实际观察、监督目标与可追溯来源。`choice`、`noul`、`score` 分别表达离散选择、布尔判断和有序等级；使用哪一种、提出几题由当前任务与材料决定，不要求每条五题或齐备全部题型。具体可执行版本以平台 `datasets/source` 返回的 `extraction_contract` 为准，调用步骤由[抽取 Skill](../../.agents/skills/decision-sample-extraction/SKILL.md)维护，不在这里重复接口 schema。

## 决策时点与证据

先确认目标业务轨迹的角色、采集状态和完整性；评审、归因记录不能当作业务决策。完整请求快照优先；只能从之前事件重建时记录 reconstructed，缺少当时工具目录时不声称比较了所有工具。只有最终摘要或缺输入的切片可以跳过，允许零样本。

当前动作之前的用户输入和已返回观察可用于题目；当前动作结果及后续证据只供复核，不放入 `state`、问题或候选描述。并行调用的选择共享同一决策前材料，不能按落盘顺序将同批另一调用的结果倒灌。题目必须属于服务器选定的 `decision_id` 所在决策，不能用后来的决策考已经执行的前一步。`assistant_response` 只是动作类型，不证明待评回复已出现在输入；质量评分要求当前 `state` 完整包含被评对象，缺少对象时不能给这条回复打分，也不能另造事后评分任务。

固定流水线、重复轮询、复述角色职责或输入已直接给出答案的题目通常没有足够判断价值。需要后续工具结果才能回答时选择正确的更晚切点；不能把业务结论挂到最初加载 Skill 的动作。问题、候选描述和推荐依据中的事实须能在本切片输入定位，只记录可核对的外显证据与推断，不要求私有思维链，不补造工具、授权或执行结果。

流程与任务说明真实行业场景和当前决策目的。可从已有安全事件、客服、发票或智能体运行记录提炼相应判断，但没有某类材料时不为覆盖行业名称虚构输入。补证、暂停或升级在当前流程确实可选、且可见材料足以支持时，本身就是有业务价值的决策；任务不清、选项无据或被评对象缺失导致的无法标注则应跳过，两者不能混称为“证据不足”。

## 标签与复核

同一输入的各个命名问题分别描述规则，目标独立记录硬标签或可选概率、来源、依据和复核状态。`choice` 使用互异候选键，`noul` 是布尔值，`score` 是有序等级的零起始下标。一次问一件事，类型合法仍需判断问题、选项和标签是否在当前时点成立；候选与等级的解释属于输入，目标和构造元数据不成为答案提示。

任务明确监督语义：`observed_action` 学习该时点实际采取的动作，只支持真实行为标签，不声称动作正确或最优；`recommended_decision` 依据当前输入判断应该怎样做，原轨迹行为仅是核对信息。两种目的不能混用，Run 成功或工具成功也不能证明每一步正确。行为标签需对应真实动作，推荐题则需有可定位的状态内依据。

三种题型均可使用硬标签，也可在来源明确时使用完整候选或等级上的概率分布；硬标签不自动转为 100% 概率。分布的完整性、数值范围和归一性只证明格式合法。人工硬标签、模型单次建议、教师多次采样聚合应分别保留真实来源与方法，不得互相冒充；某种概率格式不能证明其已经校准。AI 抽取的推荐目标固定为 `model_suggestion`，真实行为目标固定为 `observed_action`，保存时均待逐题复核；生成软标签不能使其成为教师聚合，也不能替代人员真值。

每题依据区分当前实际动作、基于可见材料的推荐判断及不确定性。后续结果可明确标为事后观察，但不能成为当时已知事实或推荐的唯一证明。失败轨迹可支持失败分析，不能强行标为正确训练答案。AI 抽取目标默认 `suggested`；复核者逐题核对时点、输入可答性、任务语义、问题和规则、目标来源及依据，再确认标签。修改题目、规则或目标后重做受影响题目的复核，不能沿用旧确认。

用户可明确委托 AI 复核。普通管理会话通过 `datasets/review` 记录实际 Session、模型、时间及 `functional_validation` 用途；改写标签保留 `ai_annotation` 与原始来源，逐题复核标记为 `ai_delegated`。这项记录不表示人工或独立真值。固定抽样专项仍只生成待复核候选。

来源路径、必要 Run 文件集合的摘要、行号、固定来源组及复核状态由平台维护；助手只提交当前合同允许的候选字段。预览、保存、逐题复核和合格导出均须核对真实来源与输入一致性。来源缺失、改变或输入损坏时，可阅读的候选事实继续保留，但不能作为合格训练或评测数据。来源变化后重读，已人工编辑的样本不被重新抽取覆盖，新抽取作为独立批次。原始 Run 保持不变；旧格式可读及候选下载，不自动升级成新版合格记录。

## 去重、划分与导出

同一真实任务或事件、同 Session 的相关步骤、跨 Run 重跑和改写应保持关联，跨批次也不能分散到互斥用途。平台固定已知来源组；人工分组只能补充关联，不能通过改组名擦除已知同源关系。内容摘要只发现精确重复，近重复需复核，不自动宣称语义唯一。少量样本保持 `unassigned`，不为了凑比例强划 train/test，未分配也不默认成为训练数据。

训练、开发、校准和测试用途需显式指定并分别留出：仅 `train` 用于训练导出，其余用途由对应入口导出，不混入训练。标签与教师一致不等于业务正确，校准与泛化需要独立证据；选项换序、改写和未知情况应在后续模型评测中验证。当前抽取功能只准备和导出数据，不宣称模型训练、概率校准或资源收益已经成立。

样本文件是当前可编辑事实源，JSONL 是按需导出产物。保存后在本 Run 的决策样本中逐题复核，资格由服务端按来源、复核与用途共同计算；候选下载保留真实状态，不能与合格训练或留出下载混称。

## 研究依据的适用范围

本次结构参考 [LocalLLaMA/typed-decisions 的固定版本](https://huggingface.co/datasets/LocalLLaMA/typed-decisions/tree/7189f46b02248bd2569df7325c9df8e3b24e90a7)（Apache-2.0）：共享 `state` 下的命名问题、类型与规则、独立监督分布及构造来源。借鉴结构，不导入整套数据；其中教师多次采样得到的 `gold` 不等于人工真值，平台单次模型建议也不能自称具有相同构造依据。

原研究结合用户提供的决策模型资料、Kev 固定版数据读取合同，以及 Agent Lightning 的局部决策、过程监督、AgentTuning 的轨迹质量、去重与分组划分、教师标签及校准分离方法。它们支持数据构建选择，不证明本平台数据或下游模型已经通过质量验收。Kev 旧版格式属于历史互操作依据，不能覆盖当前程序的版本合同。原资料摘要、一手论文及接口链接保留于[固定来源](README.md)，采用外部新版本时另行核验。


## KEV 原生训练交接

逐题复核并明确用途后保存平台实际导出回执；kev-trace-pipeline/scripts/platform_export.py 支持 choice/noul/score 的 v2 到原生格式转换，保持标签、软分布、来源和用途。转换与原始轨迹 IR 是两条输入路径，不能把 IR verified 当作平台复核回执。真实回执缺失、未分组、同源跨用途或来源核验不通过时阻断；不靠新组名或重写摘要修补。

详细办理路径见[算力变体研究](compute-variants.md)与[KEV 技能配置](kev-medium-variant-skills.md)。当前固定抽样任务到保存与回读结束；后续技能不通过改变会话范围接管当前任务。
