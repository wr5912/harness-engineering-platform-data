# KEV 数据格式与可读输出整改

日期：2026-10-26。对象：平台管理助手的 KEV 技能、离线数据脚本和训练交接。

## 目标

训练、开发、校准和测试数据保持精确的 KEV 格式。决策点清单、方案、审查与执行结果先让人看懂：说明做成了什么、哪些问题影响使用、需要继续处理什么。程序需要的状态、来源摘要和完整诊断另行保留，两种表达使用同一组事实。

旧八类路由 JSONL 的基础结构可以继续使用。整改补齐来源、复核、保组切分和训练接入；不把旧表格数据改称 DSH 轨迹，也不把“低确定性”随意换成概率。新 DSH 数据使用有明确边界的输入构造器。

## 整改计划与落实位置

| 要解决的问题 | 修改方式 | 验收依据 |
|---|---|---|
| 用户先看到 JSON、状态码和内部术语 | 在 user-facing-output 统一约定人读/机器产物；数据、桥接、训练准备和编码脚本默认中文摘要及 Markdown 报告，保留 --json | 成功、待复核和失败的 CLI 场景；机器回执仍可解析，数据文件不被改写 |
| 三种格式容易被混用 | 汇总 IR、平台 v2、原生 KEV 的字段、类型、监督与来源边界，加入合成原生格式例 | 示例通过实际格式检查；不把原生合法说成已满足平台导出资格 |
| 旧文件没有合适入口 | legacy_native.py 提供 inspect、真实复核、build、audit；保留原字节和复核快照，训练器加入 legacy-native | 合成旧数据到训练计划的完整链路；缺复核、摘要过期和改动派生文件均不能继续 |
| 导出显示通过，但旧 ID 或 variant 无法被训练入口消费 | 派生记录使用稳定唯一 ID 和明确的 clean 用途，完整保留原元数据 | 缺失、空值、数字及重复旧 ID 均经过真实消费链核验，不修改源文件 |
| 默认 state 切分可能拆开已有来源组 | 全量原输入先建立 group/family/session/相同输入闭包，再按复核结果筛选和分区 | 同组、跨题包装、被排除中间记录等保持关联；四个用途不交叉 |
| 监督或未来信息混进模型输入 | 三条入口核对输入边界，旧原生数据复用共享根字段检查；隔离并保留原文 | gold_label、future_tool_result 等明确保留字段被隔离，合法嵌套业务字段不被误删 |
| 不同 JSON 写法或字段排序改变真实输入 | 比较固定 KEV 渲染后的输入，保留原对象顺序，并检查同输入冲突标签 | 对象/字符串同文不能跨用途；导出不改模型所见输入顺序 |
| 复核记录已改变但旧方案继续可用 | 编码检查前后、命令放行前核对源与复核快照 | 修改复核状态后必须重新构建和准备，旧编码回执不能放行 |
| 不确定样本仍作为确定硬标签 | 独立记录复核状态、依据和方式；歧义、未标注、无效项隔离，不自动补概率或金标 | 未复核模板不能构建合格四分区；低确定性本身不改变监督权重 |
| 八类路由没有专用轨迹构造器 | cybersecurity-routing-v1 只处理初始用户请求的首个路由边界；固定八类问题，复用纯输入构造函数 | 当前/未来动作变化不改变输入，真实用户背景变化影响输入，后续步骤不重复抽样 |
| 文件齐全但某用途为空也可能通过检查 | audit-dataset 明确要求四个非空用途，训练器继续复核 | 空开发/校准/测试文件的失败场景 |
| 较弱管理模型容易跳阶段或混淆完成含义 | 单题提交、固定入口、真实参数、阶段状态和可读下一步；扩充行为场景 | 独立试用；目标模型成绩仍需实际模型调用，不用脚本测试冒充 |

## 验证方法

在 kev-trace-pipeline/scripts 与 kev-training/scripts 分别运行 `python3 -m unittest discover -s tests -v`。原生兼容检查使用与套件固定版本一致的 KEV_UPSTREAM_ROOT；缺少它时必须说明跳过，不称为已验证。新增脚本必须运行真实 CLI 验证成功与失败，不能只检查文档或字符串。

旧文件只做只读检查和待复核材料生成。真实标签未完成复核前，不批量写 verified、不构建假合格数据、不训练。公开测试仅使用人工合成夹具；用户原始数据和轨迹不提交仓库。两份官方 Skill 的原始文件保持固定版本，适配在本套入口和独立脚本完成。

## 现有使用方式如何迁移

- 依赖命令行标准输出 JSON 的程序显式加 `--json`；四份训练/评估数据及状态文件继续采用机器格式。普通使用默认读取中文摘要和 `report.md`。
- 旧版 IR 编译产物需从已复核原始 IR 重新编译、分区，获得新增的实际输入顺序摘要；不能手填摘要跳过检查。既有原生 KEV 文件走独立旧数据入口。
- 数据检查通过后，先由 `kev-training` 生成计划，再按计划完成真实编码检查，最后才可取训练命令。复核快照变化后，旧方案及编码回执不再放行。

## 当前交付边界

本次交付技能、数据工具、可读报告和训练准备能力。结构与来源记录自洽不等于标签语义正确；来源闭包也不能识别从未声明的任务关系。实际 tokenizer、GPU 训练、部署、完整任务等效和 GPT-5.5 等目标模型表现分别取证。

现有“请 AI 策划算力变体 → 中算力变体”仍是策划任务。平台没有新增训练作业执行器；旧数据导入不新增线上菜单或绕过平台复核。普通获授权离线任务可使用新脚本，最终训练与变体接管仍使用真实能力和来源。
