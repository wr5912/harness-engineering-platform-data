# 算力变体研究

研究同一个业务任务能否以更少资源保持约定效果。每个变体从同一 Agent 完整可恢复的固定父版独立派生；当前平台可实际使用固定 Git 来源，Research Release 是历史资产模型概念，不是当前可调用的创建或装载入口。

## 先解释成本在哪里

先读代表性 Run 的实际输出和工具结果，再查看相关决策。重复请求、长上下文或多个子任务可以提示成本来源，但调用多本身不证明浪费。分清实际观察和待验证假设；没有 Run 时可以提出假设，不伪造诊断。

优先研究减少无新增信息的调用、按阶段读取上下文、复用有效结果或把确定步骤编排为工具；保留关键复核、纠错与异常。缓存需要有效输入和更新条件，摘要不能丢掉失败证据。默认继承业务父版实际模型与推理配置，只有用户明确选择才研究模型变化；管理助手模型不替代业务模型。

`no-compute`、`low-compute`、`medium-compute`、`full-compute` 仅描述研究目标，不是固定产品等级。声称无模型调用需实际调用证据。动态选型必须是已明确的假设，不能在运行时无记录切换。

## 冻结共同任务与资源口径

冻结 Case、关键任务、非关键通过率容差、每个 Case 的独立次数、资源指标和最低收益。选择理由与风险对应，界面默认值不保证统计充分。需要新增 Case 时先确认保存并冻结，不在结果出来后降标准。

完整计划和目标资产在独立比较前固定；双方的新运行须记录同一冻结计划，父侧 Candidate 与固定父版一致。旧 Run 可用于诊断，不能追认为冻结后的新比较。同一 Run 重复选中不构成独立重复。

资源维度分别记录模型调用、输入/输出 Token、耗时，以及实际可采集的费用和本地硬件。计入子 Session、重试、评审和外部模型；未采集项保持未知，不将 token 当硬件算力或账单。共享外部后端、不同服务负载与未观测调用可能混淆收益，需要单列限制。

## 有限选项模型作为候选

先分开确定规则、有限选项判断和开放式分析。有限选项模型可研究路由、阈值判断或补充信息决策，不能代替完整研判和真实工具结果。接口兼容、类型合法或一次路由正确不证明任务等效。

历史资料研究过 Jev、Laya 及 DSH 社区接入：远端 API 与本地权重是不同算力与许可条件，插件安装不证明减少主模型调用。采用前重新核对官方模型版本、接口、许可、算力与中文输入能力；外部状态不从历史笔记推定当前可用。具体历史来源与版本见[来源索引](README.md)。

每次只改变可解释的因素。共同验证正常输入、误分流、不确定时的回退、中文和边界输入；效果与成本分开判断。单个判断点可先试验，但不能外推成整个 Harness 等效。

## 决定与边界

比较既看任务质量，也看资源证据及来源可比性。关键任务退步、两侧都失败、重复不足、输入变化、资源未知或收益未达标都不能认定等效。保留 continue 或 inconclusive，不放宽原计划让比较通过。

平台的 `eligible_for_end` 只是当前计划下的条件判断，不代表总体任务分布上的统计非劣性。人员复核实际 Run、输出与完整工具结果后，由界面确认 `end`；助手不伪造确认或直接写状态绕过。终端身份限定继承关系，不代表发布、实例切换或所有环境成本更低。
