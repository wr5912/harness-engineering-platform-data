# 来源固定、能力继承与融合

Experiment 编号标识创建顺序，不代表继承关系。Baseline 是比较起点，当前 Git HEAD 也不自动代表所选版本完整可恢复。创建和决定前都需要核对仍有效的来源能力。

## 固定对象

选择同一 Agent 的主来源 Experiment，用详情中的派生来源和 `assets/read-fixed` 核对完整 Candidate、固定提交与实际内容。已选版本的 `baseline_ref` 可能是它的祖先，不能将祖先误当用户所选父版。dirty 工作树可用于观察，未经固定不得说成已可恢复；平台没有提交接口时说明需固定的对象，不静默退回旧版。

盘点工作区可访问的同 Agent 版本与来源建议，结合任务保留仍有效的主线和并行能力。平台目录未覆盖远端或其他工作树时明确范围，不声称已查全。选择 `inherit` 或 `omit` 都需理由，能力被替代时说明替代和回归证据。

所有变体都不能作为后续继承或融合的来源，该限制不取决于是否 `end`。`end` 只表示限定任务的效果与资源证据满足冻结计划并经人员确认，不决定继承资格。低算力名称、计划字段或一次成功都不改变这个边界；新主线对应的新变体从普通业务版本独立派生。

## 融合到独立目标

多来源融合采用一个主父版和独立 Candidate，记录其他固定来源、保留能力和冲突取舍。来源声明完成不代表集成完成。比对源码、生成制品、Preset、插件注册与依赖、MCP 工具范围、Runtime 锁、启动配置、卷挂载和实例设置，重点检查共同修改的消费者。

文件差异检查只能发现变化或缺失；它不能证明语义兼容，不能发现根本没纳入清单的来源。预期变化需要说明取舍，无须把目标机械还原为来源。读取被截断或仅返回二进制元数据时，不用不完整内容重建目标。

构建和检查针对目标 Candidate 的真实生成物。来源自身测试通过不能代替目标融合测试；生成物与正在运行实例的实际来源也要一致。复用平台 `fusion/*` 的已确认检查与真实回执，不另造可编辑并行清单或运行任意来源脚本。

## 行为验证

用新 Session 或新实例检查各来源至少一个有区分力能力及一个组合场景，再补直接受影响回归。涉及 Web、MCP 或外部服务时，分别验证用户实际入口、真实工具调用和业务产物；依赖不可用时限定结论。

源码写入、构建成功、配置标记和 HTTP 成功各证明局部事实。只有来源、当前资产摘要、约定 Case 和封存 Run 对应，才能认定该项行为验证成立。最终回读融合状态与 Decision；两者不自动切换实例，也不等于生产发布。
