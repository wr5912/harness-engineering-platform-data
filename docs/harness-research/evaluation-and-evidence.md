# 评测、证据与研究判断

研究评测需要回答“变化是否在声明范围内改善了任务”，并保留支持、反对和未知证据。结果按实际来源判断，不能用流畅的解释替代事实核对。

## 口径与输入

Agent 的 `evaluation.md` 是当前业务 Case 的唯一维护位置，每个 Case 聚合名称、用户输入和可核对的预期；运行按研究问题显式选择。Run 保存选择及输入快照，属于历史执行事实，不是另一份可编辑用例库。具体格式见[研究评估合同](../../.agents/skills/research-eval/references/experiment-contract.md)。

同一 Agent 的版本和算力变体共用业务用例。预期描述用户任务的处理过程、可观察结果及必要的授权、失败和恢复边界，不规定调用或不调用 KEV、特定模型、编排框架或内部函数。实现装载、路由轨迹及资源收益在项目测试、Experiment 计划和 Run 中单独核对，不能写成所有实现必须遵循的业务路径；用户明确要求的业务能力和访问边界仍须保留。

工具优先使用已核验 API 文档中的名称、operationId 或清晰的中文能力名称。MCP 分组、连接名、命名空间及运行时工具 ID 不作为固定预期；每次运行按当前接口文档和实际工具目录映射能力，并以真实调用及回执核对。不能因入口改名误判能力缺失，也不能猜测接口或把未执行的能力判为通过。稳定的接口字段及业务协议可以保留，私有实现字段不作为业务验收条件。

预期使用可核对的过程与结果模式（pattern）：对象来自本次输入，状态、标识、数量、时间、链接和产物对应同一次真实回执，允许自然表达与等效实现差异。不把某台主机、实例名、模型路线、旧 Run 或一次查询结果固定为所有环境的答案；真实用户输入、固定测试数据及明确的业务阈值不因此改写。正常任务须取得所需真实结果，依赖不可用时保留失败或未知证据，不能用一段缺口说明替代正向任务通过。

最小比较可从少量有区分力输入开始，扩大结论时再补覆盖、边界、反例和已知回归。不固定 Case 数或分数阈值。动态事实按同轮真实工具结果核对，不固定某次数据值或措辞。工具型任务的正确行为包括必要调用与完整产物，不能把拒绝必要工具一律评为正确。

同一次比较固定 Harness、输入、模型、运行方式和判断口径；必要改变后重跑受影响部分。基于失败 Run 新建 Case 时取冻结输入并回到真实需求确定预期，不将错误输出变成标准答案。技术装载与界面冒烟单独验证，不混入业务评分。


## 数据与任务表现

数据建设先对应明确的业务场景、任务节点与能力目标，再确定所需内容和使用方式。知识资料、评测 Case、执行轨迹、监督标签及训练产物分别判断，既有资产可满足需求时直接复用。检查典型任务、必要边界和已知失败是否有证据支持，覆盖不足如实说明，不通过虚构场景或重复样本补数量。

数据来源与处理过程保留可追溯关系，区分真实业务、模拟和合成材料，核对时效性及当前任务能否实际消费。过程数据关注决策前可见状态、真实工具动作、结果与异常反馈；结构完整不等于事实正确，标注格式与复核记录也不能替代领域真值。会话与日志按既有切片和引用方法使用，不将整个 Runtime HOME 作为数据资产。

数据变化的效果由固定条件下的独立任务表现检验。训练、开发、校准和测试保持各自用途，已用于定向补训练样本的测试材料不能继续支持独立泛化结论。报告同时保留通过、失败、未知与资源代价，不以模型打分或统一总分代替实际输出和工具结果。

任务失败后先核对输入、工具、环境、执行与评判，再判断是否存在具体的数据缺陷。能定位时说明缺失、过时、错误标注或覆盖不足如何影响任务，修订后按同一业务口径对照验证；暂不能定位时保留替代解释，不将所有失败归因于数据。数据本体改善与下游能力收益分别报告。

能力与场景、过程数据、质量评价和反馈闭环参考[智能体能力数据集建设参考](https://github.com/wr5912/harness-engineering-platform/blob/main/docs/standards/SOURCES.md#智能体能力数据集建设参考)。具体来源与采用边界由该条目维护，不将指南的固定量级、百分比或行业组织方式作为当前任务门槛。

## 证据分层

| 证据 | 能支持的结论 | 还需核对 |
|---|---|---|
| 文件、配置、静态校验 | 对应结构及合同成立 | 实际装载和行为 |
| 进程、HTTP、插件/工具发现 | 当前局部入口可达或资源可见 | 真实调用与任务结果 |
| 新 Session 或新实例 | 特定来源实际装载与执行 | 业务完整性、失败及回归 |
| 固定输入的新 Run | 声明条件下的任务观察 | 来源可比性、覆盖和替代解释 |
| 固定版本恢复及重载 | 该版本可复现 | 不自动构成生产验收 |

`execution_status` 与 `verdict` 分开。执行完成可以业务失败；执行错误或跳过只能判证据不足。未选场景不是通过，Trial 数不等于去重 Case 数。工具日志为空可能证明本轮没有调用，不能用推测补写。缺轨迹、缺附件、未知采集状态和评审失败都需要影响结论。

## 比较与归因

先读未选、未执行、失败和无法判断的部分，再核对通过项的原始回答与工具结果。对照必须真的存在匹配来源的 Run，工具能比较不等于已经做过比较。程序、模型、输入、工具数据或环境同时变化时，差异可描述，但不能全归因于 Harness。

自动评审和归因是待复核证据：核对直接支持、成功反例、替代解释和下一次可证伪检查。评审实例不能获得目标业务身份，参考答案和评判资料不进入被测容器。复核失败不改写原 Case 判定，历史 Run 不补造后续分析。

报告标明资料来自源码阅读、静态执行、Mock、真实工具/模型观察还是作者提供记录。历史验收证明当时行为；判断现状须沿后续引用和当前实例核实。隔离工作区记录只能证明该隔离范围，不能据此认定正式实例已切换。

## Decision

研究决定说明比较了什么、支持与反对证据、回归、失败、未知及适用限制。`adopt` 需要相应效果证据，`continue` 表示值得继续验证，`reject` 表示否决本次变化，`inconclusive` 表示证据不足。结构化状态与正文一起保存和回读，不用一段肯定文案替代状态更新。费用、Token、延迟和硬件资源按真实采集填写，不能从不完整统计推算精确总成本。

业务效果复核对照完整的冻结输入、预期、实际回答、工具结果和产物；源码诊断另行核对锁定资产、机制及替代解释，分别报告结论和未核实范围。源码未读齐不能证明源码正确，也不覆盖已完成的业务效果复核；效果通过同样不能证明源码没有问题。比较双方采用相同的复核口径，口径变化后保存新的对照 Run。
