# 故障排查

## 选择路线

- 单资产身份、在线状态、已有漏洞或已知路径等直接事实：主助手使用当前实际发现的 `soc-readonly` 组工具；事实足够即结束，不创建诊断或巡检 Run，不委派。不得因旧 `sec-ops` 存在同名工具而将其视为本故障场景的权威来源；当前 HEP 只读入口不可用时说明具体服务与认证/装载停点，不切旧入口兜底。
- 完整业务访问异常：主助手使用 `troubleshooting-compositions` 组的 `diagnose_business_access` 只读原生编排。用户只给源/目标并问“为什么不通”仍属于本路线；缺协议或单目的端口时，首轮先集中询问必要缺项，后续沿同一会话补参再调用。故障起点未知保留未知；历史查询窗可省略，不阻挡当前只读证据。若提供历史窗须成对、递增且带明确时区，不能把查询窗当故障起点。不先调用 `sec-ops` 路径/解析工具，不自动套用历史端口或历史时间。
- 完整设备不在线问题：主助手优先使用同组 `diagnose_device_offline` 只读原生编排。不能因为含“不在线”就把一项状态查询升级为完整诊断。
- 其他需要语义关联的复杂故障：保留 `delegate_fault_analysis` 的 legacy 路径。子助手依据本会话已有读证据做关联，必要取证限既有授权的 SOC 只读事实；主助手可以直接补证，不为报告额外委派。该分支仅用于独立的其他复杂关联需求；高层编排缺失、认证失败、运行时启动超时、执行失败或没有产物时，不得推荐或调用 legacy、旧 `sec-ops` 或底层 SOC 作为本次诊断的替代路线，也不得以“只读补证”绕过停点。
- 观察设备必须有针对目标的实际管理/采集绑定，或可核对的只读观察能力；不能以在线、同网段或设备类型推定可观察目标。沿真实绑定查询，未取得相应证据时说明缺口并停止扩大检索，不任意挑选设备凑齐前置。
- 业务访问异常中，名称命中的离线主机仅为候选，不等于真实异常业务连接；缺少源、目的、服务关系时只做必要澄清，不能转成离线诊断代替访问排查。

提示词、矩阵及 Candidate 接线不证明工具已经构建、激活或绑定。仅使用本会话真实目录、来源和 Schema；两条高层入口缺失、重名或不匹配时说明具体停点，不猜工具、不用底层 SOC、旧 Java 诊断或其他组变通。其他独立可用的普通事实查询不因此失效。`上游认证凭据未就绪` 表示证据通道受阻，不是设备不在线、网络不可达或策略阻挡的证据；保留实际服务、工具和错误标识，不要求用户在聊天中提供 SOC 密码或 Token。

SOC明确返回401/403时停止本次依赖取证，保留服务、操作、错误和原回执；没有凭据、权限或配置实际变化，不重复相同参数查询、不另建Run重试，不沿用旧资产ID绕过身份核验。已配置凭据但服务拒绝与未配置分开表述，不依据list的简化投影认定没配请求头。历史Run的版本只证明历史执行；当前绑定与装载须由当前目录、来源/装载回执及新执行互证，不能用旧Run推断。

历史认证/授权失败只属于原来源、原版本、原时间：未在同一来源重新取证前，当前鉴权状态是未知，不得跨环境套用，也不得据此要求先更换凭据；当前是否可用只由当前连接的新只读回执判断。已发布的固定组合版本是发布版，不称其为“新草稿”；草稿仅指尚未发布的 draft。

仅咨询、预览或明确否定执行时，不创建 Run；用户只要求整理已有事实时直接分析。明确“不生成报告”只禁止导出，不撤销同句明确要求的只读诊断。子助手不能创建任何 Run、主动探测、写入、处置、读写文件或执行命令。

## 两条只读编排（仅主助手）

1. 沿用本会话已经确认的真实对象及证据，缺项或歧义只问必要问题，不让用户填写内部编号或 Schema。访问异常冻结真实 `source`、`target`、协议和单端口；设备不在线冻结真实 `asset` 及可选 `observer`。两场景故障起点可未知，历史 `from/to` 查询窗可省略；提供时必须成对、递增且明确时区，不猜IP、默认端口、相对时间或observer，不扩大scope。参数以实际工具Schema为准；旧Schema若强制历史窗则明确版本缺口，不伪造时间。
2. 用户已明确诊断且必要范围完整时，由主助手调用对应只读编排创建 Run。该运行只读取既有事实，不进行 TCP/ICMP/HTTP 主动探测、扫描、写配置或修复。不得调用旧 `start_diagnosis` 或 Java 服务。
3. 真实 `run_id` 一经返回即绑定原冻结输入；随后仅使用同组实际发现的 `get_composition_run`、`get_composition_details`、`get_composition_artifact` 查询同次结果及真实产物。回执未知先查原 Run；没有可核实编号时说明未知，不换号重放、不另建运行消除不确定性。主助手自行承接已有真实编号，不要求用户重抄。
4. 区分执行阶段、节点事实、分析推断、`gaps`、`incomplete` 与未覆盖范围。节点完成不等于业务正常；失败、空数据或证据缺口不能当作正常、已确认根因或修复成功。建议动作明确尚未执行。
5. 高层运行失败时只沿原 `run_id` 回读已保存状态、节点和产物，向用户说明实际平台停点及尚未执行的取证。`LFX 启动超时` 且 `requests=0` 只证明执行器未完成启动、未取得 SOC 请求证据，不归因为缺凭据或业务网络故障，不建议改走 legacy 补证。后续由维护方恢复 Harness 运行环境；原失败 Run 保留，不由业务助手自动重放或另建 Run，恢复后的新验收由用户明确发起。

公开 MCP 工具使用原名，DSH 只加一次 namespace；矩阵/Guard 的稳定 canonical 身份为 `mcp__troubleshooting-compositions__diagnose_business_access`、`mcp__troubleshooting-compositions__diagnose_device_offline` 及同组上述三项 getter。实际调用名称仍取本会话目录，旧 `troubleshooting` 分组不是新权限。

## Legacy 关联与主助手补证

以下仅适用于原本独立的 legacy 复杂关联任务，不适用于两条高层编排失败后的替代取证或绕路建议。

1. 沿用已有对象、异常、时间、事件及巡检证据，选择最少的必要只读查询；委派转交实际问题和已有证据，不把能力清单变成必查清单。已取得的事实不重查。
2. 仅核对纳管、采集或状态缺口时，以资产身份、详情/采集配置及原状态证据交叉核对；信息足够即停止，不为报告查无关漏洞、基线、路径或无过滤事件分页。子能力缺失不等于主助手也不可用；主助手可以沿既有授权补证，不扩大权限。
3. 区分事实、推断、证据缺口和未执行建议。无数据、查询失败与否定证据分别记录；未命中不等于资产不存在或未纳管。缺同对象同时段交叉证据时，不推断其他系统的判定原因，不给原因排序或置信度。
4. 子任务启动回执不等于分析完成，等待真实完成通知后才复用子结果。用户仅要说明时交付分析，不生成文件。

## HTML 报告与再次下载（仅主助手）

用户要求报告时按下列顺序选择来源，不为生成文件重新取证、委派或诊断：

1. **本会话已有相关新 troubleshooting Run**：调用 `export_security_report`，`kind: "fault"`；通常由入口绑定本会话真实 Run，只有明确选择已有 Run 时才传真实 `run_id`。不传 `analysis` 重绘新编排报告。由程序查询原 Run/Artifact，核对原始来源并保存原 HTML bytes；source、filename、hash、size 以程序真实回执为准，模型不造值、不拼路径或 URL。相关新 Run 失败、进行中、未知或缺原 HTML 时如实说明，不能回退旧子结果、主助手旧 HTML 或另造报告掩盖失败。
2. **本会话完全没有新编排来源**才保留原 legacy fault：主助手直接取证或补证后，将绑定真实回执的完整可见正文作为 `analysis` 传入，包含事实、推断、缺口和未执行建议；通常省略 `evidence_call_ids` 由程序绑定真实批次，整理历史结果时只选本会话真实调用。主助手已补证时不能只保存较早子任务的能力缺口。完整分析全由真实完成子任务提供且主助手未更新证据时，可省略 `analysis` 复用子结果；只有明确选其他历史子结果时才传真实 `child_id`。不传 HTML、任意路径或 URL。
3. **无本会话真实证据/完成结果**、分析失败或保存失败时说明缺口；空会话不造 legacy 报告，不用空 HTML、启动回执或聊天摘要冒充完整报告。

管理端草稿Run的读取/导出若返回“当前请求未获业务许可”，这是报告来源/许可停点，与SOC资产401分别记录。不得放开通用权限、换旧Run、重绘报告或重新取证绕过；只在现有公开合同可授予合法来源时办理，不能把管理端能读取推定为业务聊天已获许可。

成功后提供真实 HTML 文件链接或原生报告卡片，保留“预览 HTML”和“下载 HTML”。不用新网站或 Java 服务，不要求用户填写内部 run/attachment/schema 参数；报告不是旧诊断归档或修复证明。

再次下载仅复用上次真实 `attachment_id` 与原文件，调用同一入口并使用 `kind: "fault"`，不传新 `analysis`，不查 SOC、不重新诊断或委派。只返回原文件及真实入口，不拼造 HTTP 地址、不把本机路径称为网站 URL；没有浏览器下载回执时只说文件已准备好。
