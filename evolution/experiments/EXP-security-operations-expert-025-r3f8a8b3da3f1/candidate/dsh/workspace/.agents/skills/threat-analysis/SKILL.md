收到研判请求后，提取原始 `INC-YYYYMMDD-NNNNNN`，通过 `delegate_threat_analysis` 委派一次。prompt 只传事件 ID 和研判请求，不携带人工标签或已有结论。多个 ID 分别委派，不改写 ID；没有有效 ID 时询问用户。

专用子智能体仅调用 `analyze_threat_incident`。代码完成 SOC 认领、真实 MCP 取证、名单分类或五源融合、冻结输入模型推理、校验、摘要与报告、SOC 回写和报告存储。名单快速分类不调用内部模型。结果校验与业务结论是不同事实；历史研判源尚未接入。

正式摘要由程序直接交付主会话，下载链接只来自报告 persistence MCP。不得从 SOC 回写响应猜下载链接，不再调用模型改写摘要。取证、模型和存储失败均保留真实状态，不编造结论或保存成功。

## 规则优化建议

规则优化仍在同一研判工具内部完成，不另行委派规则智能体或调用策略写入工具。完整研判的误报、可疑和低置信度真实告警默认进入规则问题分析；真实告警的可配置门槛首版为 `confidence_score < 0.75`。中高置信度真实告警默认跳过，只有已有可追溯规则异常或真实用户明确要求专项规则分析时例外进入。同一规则多次命中不自动证明异常，默认开启规则分支也不等于人工指定。名单快速分类保持原输出，不新增规则模型调用或建议字段。

用户明确要求“研判事件并分析相关规则”时，在同一次委派中保留该只读任务意图，不追加人工结论或自填可信覆盖标志。例外来源由宿主核对本次真实用户及直接委派记录，不能从模型判断、工具参数、Schedule或运行背景消息自行取得。子智能体仍只调用一次固定研判工具，不自行追加规则查询、校验、写入或处置。

基础格式校验不作为规则分析开关或无法优化原因；原基础结论及校验状态保持不变。代码分别分析检测规则和关联规则，按理解目标、解释命中、具体问题、设计改动、完整候选及影响说明形成建议。没有实际修改依据时允许不给正文，不通过删除攻击信号或提高置信度文案凑优化。

对外只使用既有 `rule_optimization_suggestions`，每项为 `rule_content`、`impact_scope`、`cannot_optimize_reason`。候选格式以 SOC 提供的对应校验接口合同为准；尚未接入时只能称未校验的审阅草案，不能称格式通过、已采用或效果改善。规则来源、触发门槛、引用和状态只留独立本地制品，不往业务包络或报告添加审计表。

## 研判并处置

用户在同一请求里明确要求“研判并处置”时，委派研判后追加一次 `disposition_prepare`：`incident_id` 原样传入、`mode: "recommendation"`，由处置运行时从研判建议映射动作与目标并生成草案。只生成草案并展示，不确认、不提交、不调用策略或其他处置工具；没有可执行的推荐动作时说明缺口并转人工。该追加步骤不改变摘要由程序直接交付的约束。
