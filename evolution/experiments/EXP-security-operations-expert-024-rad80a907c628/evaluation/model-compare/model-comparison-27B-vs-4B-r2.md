## 提取口径

- 逐调用数据来自三轮评测实例 `dsh-home/sessions/--work-harness-workspace--/` 下全部 Session 日志（A 162/162、B 158/158、C 162/162，全部命中），脚本 `extract_llm_calls.py`。

- token 取 assistant 事件 `usage` 结算值（`inputTokens`/`outputTokens`）；无 usage 的辅助调用不计入 token 合计。

## 观察

- **4B 整体比 27B 快约 2 倍以上、输入 token 省约 79–80%**，主要省在子智能体：27B 的输入 token 有 90% 消耗在子智能体会话（625 次调用、2935 万 token），两轮 4B 只委派 153/177 次（−75%/−72%）。
- **4B 的主会话调用反而更多**（400/462 vs 293，+37%/+58%），说明 4B 把同样流程拆成更多轮次、每轮上下文更小；调用次数少不等于任务做得少。
- **两轮 4B 输出形态的悬殊主要由思考模式解释**：Qwen3.5-4B-思考 轮输出 token 总量 193,901 反而高于 27B，评审平均每次输出 1,020 token（三轮最长）却全部不是合法 JSON——生成了很多但格式不对；Qwen3.5-4B-无思考 轮评审平均只输出 259 token 就结束（57/69 非 JSON），耗时也从 P50 12,910 ms 降到 3,039 ms。开思考轮次输出更长、更慢，但评审可用性反而更差。
- **子智能体单次耗时也是思考轮最慢**（Qwen3.5-4B-思考 P50 6,564 ms，比 27B 的 3,698 ms 慢 77%），无思考轮反而最快（2,818 ms），与思考开销方向一致。
- 上述是速度与资源证据，不构成效果结论：4B 两轮的评审有效性为 0/69 与 11/69，效果数字均不可与 27B（56/69 有效）直接比较。
