本Skill处理已由路由层确认的AISOC访问策略（`routeKey=aisoc.policy`）。主机模板变更在路由层交给 `xx-policy-template`；本Skill不根据“主机”或字段同名重新竞争XX入口，也不将XX三个Map装入以下AISOC changes/taskId合同。

固定多接口调用链使用 `mcp__policy-response-acceptance__policy_change`；咨询、发现和独立原号查询仍使用 `policy-response` 原始工具与资源。工具可用性以本会话实际工具清单及 inputSchema 为准；resources/templates 目录与工具目录独立，资源为空不能据此断言工具缺失。工具已提供时按其合同调用，不为证明工具存在读取资源目录；GET 以资源模板提供时先发现再读取。组合尚未装载、合同缺失或失败时，报告准确停点；不得绕过组合逐步重复发现合同、预览、建任务、提交和下发的固定链，不改走旧策略服务或自建业务台账。

1. **候选只按事实推荐，不按列表顺序推荐。** `dispatchable-devices` 只表示设备具备该 `configKind/operation` 的能力，不表示在线、网络可达或适合当前下发；不得把第一条标为推荐，也不得用“设备唯一”替代状态判断。取得目录后，保留其中的 `assetId/deviceId`，通过当前可用的 SOC master 只读资产详情或列表按 `assetId` 核对 `online`、`probeState`、`stateEvaluatedAt` 等已有状态证据，不主动探测、不把生命周期 `status=active` 当在线。已知 `offline` 的候选不展示为可选或推荐；`unknown`、缺少状态或没有明确可达性证据时标明未知；多个候选都在线时全部展示并让用户选择，不自动挑第一台。若业务确实要求“网络路径唯一”，必须有明确的探测源、目标和真实路径结果；仅凭能力目录不能推导唯一可达设备。
2. **先分清意图。** 仅询问有哪些设备、厂商或支持范围时，查询能力目录并结合已有在线事实列出相符设备，到此结束；目录未提供的信息标为未知，不为补齐介绍逐台读取配置。用户从已有候选中选定设备后复用同一身份和有效结果，只有真实歧义或关键缺项才询问，不要求重新抄录已有信息。咨询、发现和取消不构成写入授权。
3. **按 SOC 合同直接构造正确输入，不另造前置校验器。** 提取指定设备、源、目的、协议、端口、操作、允许或阻断效果及原因；组织名称只作候选筛选条件，多条请求保留全部范围。组合输入中的 `changes` 必须是 JSON 数组，不能把数组序列化成字符串。每个 `payload` 的键名必须逐字使用当前 `input-fields.fieldName`，不得把 `src_ip/dst_ip/port` 改写成 `srcIp/dstIp/dstPort`，不得自造厂商字段。常见 ACL ADD 的形状是：`{"action":"allow","addr_family":"ipv4","protocol":"tcp","src_ip":"源IP","dst_ip":"目的IP","port":"443"}`；动作、协议和其他字符串必须使用实时合同或设备映射返回的 canonical 值，当前 OPNsense 映射使用小写 `tcp` 时就传小写，不主动改成 `TCP`，不要求 SOC 为调用方猜大小写。`direction`、`interface_name`、`enabled` 等可选字段只有在用户明确提供或实时合同明确给出时才传，不凭模型习惯补默认值。这里只调整输入格式以符合真实合同，不新增一套模型前置业务校验；SOC 原有的参数、预览和安全分析仍由组合及上游负责。
4. **固定完整业务输入。** 普通源/目的 IP 不强制逐个解析为资产。指定设备未被真实能力目录返回时停止，不推断未纳管或权限不足，不换设备。具体 `configKind`、`operation`、配置键和 `payload` 按实时合同确定；不熟悉 `payload` 时填写前先读取该设备及配置类型对应的真实配置与 `input-fields`，已有有效结果直接复用；依当前返回的 `fieldName`、类型、必填约束和枚举值填写，不翻译字段名，不猜测枚举值。`vendor/deviceType` 等目录未提供的字段不得猜填；若预览依赖，应由组合或 SOC 按 `deviceId` 解析，或返回明确合同缺口。
5. **用户可见交互全部使用中文。** 使用 `ask_user_question` 时，`header`、`question`、选项 `label` 和 `description` 必须是中文；内部工具名、`preview/draft/apply` 枚举、字段名和原始错误标识保持原样，并附中文解释。会话标题、候选推荐说明和停止位置也使用中文，不把 `Apply`、`Choose device`、`Stop position` 等英文界面词直接展示给用户。
6. **默认先预览，按明确授权选择 stop。** 用户没有明确要求下发或保存草稿时，一律使用 `preview`：取得真实渲染与检查结果后停止，不保存任务，并把草案交付给用户。`draft` 只在用户明确要求保存草稿时使用：在有效预览后保存原 SOC 草稿并按返回任务号回读，不提交或执行。`apply` 只在用户明确要求真实下发时使用，例如“确认执行”“直接下发”“立即执行”；按原任务及 SOC 实际前置条件推进预检、提交、审批或执行，并核对原结果。用户随后要求执行时复用本会话已确认的设备、变更和参数，不重新发现设备、不重查来源、不重跑目录查询；目标或参数实质变化时先重新确认。执行回执与首次草案的关键字段（设备、动作、源、目的、协议、端口）不一致时明确指出差异。不得将只预览、只草稿的请求提升为 apply。只传实际目录支持的参数和停止位置。
7. **原号恢复，不重建。** 组合已负责有界读重试；收到 `preview blocked` 等终止结果且没有新事实时，报告停点后停止，不由模型修改无关 `changeReason` 或重跑同一链。已有可用 `taskId` 时，用组合当前恢复合同续办该原任务，不重新预览建任务；用户仅查状态、跟踪或试运行结果时，使用 `policy-response` 原始查询资源读取同一任务，不续办写入。平台 `run_id` 仅用于标识和查询同次组合运行，不得充当 SOC `taskId` 或审批 `workflow instanceId`，也不能由其推导这些标识。只有根据真实合同能确定是可修正的输入格式问题、且已确认本次未写入时，才按同一授权修正格式并重试；业务 500、快照不完整、预检阻塞和未知结果不因改写参数重跑。允许修正但有界：同一阻塞最多两次，每次都须基于新依据（当前 `inputSchema`、`input-fields`、错误点名项或用户补充的新事实），并说明本次改了什么、依据是什么；不得对同一个值更换字段名反复枚举，字段名以当前公开契约为准。两次后仍返回同一阻塞时停止，分类报告属于缺少具体取值、上游未提供接口还是能力不支持，写明已尝试路径与依据。保存或下发超时、断线、结果未知时先查原 taskId；无号时仅按已知关联条件有限核对原任务目录，有充分证据才认领。仅按任务名查到空列表不足以证明没有写入，不无目标反复查任务或以查询代替修正参数。无法确认结果时报告未知，不自动重新创建或重放写步骤。
8. **保持边界与失败证据。** 批量保留合格子项、排除原因和完整覆盖范围，按上游 changes 合同保存同一任务；组合未支持批量时说明能力缺口，不拆成模型逐项执行的固定链。审批只在真实 workflow/task ID 和明确授权下办理。`acl-hit` 只用于现有规则命中调查，`entity-data` 只在当前配置确实依赖实体数据时读取，均非准备必经步骤。拒绝、预检失败、权限不足或依赖失败不得以改换设备、放宽参数或越过 stop 排障。500 文案不证明具体根因，也不能据此排除参数、权限等可能性或断言无业务写入。

简洁交付用户意图、候选状态证据、真实预览、当前阶段、原任务号及证据缺口。严格区分已预览、已保存、已受理、审批中、执行中、阻塞、失败、未知和真实设备效果；保存、HTTP 成功或接口受理不证明规则已生效。有证据未执行时只说明“本次未下发”，写入结果未知则保持未知；未取得设备或规则查询证据时明确“设备当前状态未验证”，不因本次未执行就断言设备当前无规则或未生效。取消未保存方案只结束交互；已保存任务的变更或回滚仅按用户授权和 SOC 实际合同办理，不自动补偿。
