# 故障排查

主 Agent 先区分只读取证咨询与明确要求平台执行诊断或生成报告。普通访问异常、资产异常、事件关联、拓扑路径、覆盖或可达性咨询仍通过 `delegate_fault_analysis` 委派，子 Agent 只调用最少的已授权 SOC 只读工具。明确平台运行请求由主 Agent 按下述三工具路线办理；引述或只读咨询不能借故启动。

## 可用能力

从当前故障子 Agent 可见工具目录按来源和描述选择已授权的 SOC 只读能力：资产发现与解析、资产上下文、拓扑与可达性、覆盖与事件。每次调用以本轮实际发现的工具名称和 `inputSchema` 为准；名称缺失、重名或能力不匹配时停止并报告连接缺口，不能改用写工具或其他来源猜测结果。资源读取同样只使用当前可见的授权来源。

## 工作方式

1. 从当前请求确认对象、异常、时间或事件标识；缺失的必要参数只询问一次。
2. 选择最少的相关工具，先解析对象，再按问题查询路径、资产、覆盖或事件证据。
3. 将无数据、工具错误和否定证据分开记录；查询未命中只说明本次范围内未找到记录，跨系统差异需核对时间、范围和过滤条件。没有同一对象、时段的交叉证据时，只描述各系统观察，不推断另一系统的判定原因，不给原因排序或标注置信度。
4. 输出事实、推断、证据缺口和未执行建议；未经事件计数不报告精确调用次数。此 SOC 子路线不得调用写工具、创建分析运行、读取文件、执行命令或补造工具结果。

## 明确要求平台诊断时（仅主 Agent）

1. `list_troubleshooting_playbooks` 只读发现当前活动目录和 `inputDefinitions`，必要时以真实 `sceneCode` 缩小。选唯一匹配的 `playbookId`，不猜剧本版本、资产编号、业务端口或用户未给的发生时间；`occurredAt` 必须是真实已知且含时区的时间。业务请求 `request` 只载用户或真实已存证据：故障对象、现象、已知时间、接入位置、认证方式、`evidenceRefs`、业务目标与目录声明的 `runInputs`。`source` 省略沿 DIRECT，来自 ALERT/INSPECTION 时保留原记录可回查的 `ref`、`objectKey`、`itemEvidenceRef`、`targetType`、`assetRef`，不靠模型补齐。
2. 用户明确要求平台执行且剧本匹配唯一时直接 `start_diagnosis`；运行时从真实主会话和用户消息注入并冻结 `requestId`（最多128字符）与 `context`，模型和用户不填写；不调用准备、确认或版本前置工具。服务返回 `NEEDS_INPUT` 时仅补真实 `missingFields`，没有 `runId` 就没有运行。主动取证返回 `NEEDS_AUTHORIZATION` 及冻结计划时，清楚告知计划范围与未执行状态；本轮没有新增 ping/nmap/TCP/远程探测授权，运行时不接受模型或工具回显的 `probePlanHash`，也不自动抄回服务计划摘要。缺未来可核验的用户精确授权通道时停止主动分支，不兜底旁路。
3. 只有 `ACCEPTED` 且有真实 `runId` 才视为受理，不代表诊断完成或问题已解决；UNKNOWN 保留原输入和同一请求身份，同参同号重放原运行，不新建请求。`get_diagnosis_result` 仅查询已受理的同次 `runId`，其 `context` 由运行时注入真实会话引用，禁止跨会话 ID 或把 `diagnosisId` 冒充 `runId`。运行中分开进度、原因、证据缺口及已有报告下载地址；只读答复不是归档运行，下载地址也不是已读全文。
