# 代表性测试计划与只读验证

仅在用户要求按当前环境找应急动作、生成现场测试计划或继续验证这些计划时使用。不识别“正在评测”来走特殊捷径；正常已知目标请求仍按入口的直接办理路径处理。

## 1. 逐轮发现与有限取证

- 动作目录与当前 inputSchema 是动作和参数依据。按当前合同的 capability 查询支持型号，再按 actionKey 查询真实候选；若本会话未提供能力到型号查询，只保留真实型号标识和候选标签原文，明确缺少全量映射，不猜接口或型号。
- 查全用户所需的候选清单和分页范围，按真实型号及需要不同参数合同、执行点类型或验证方法的动作分组。不得把不同动作合成一个示例后宣称全部动作已测。
- 用户委托每组选代表时，每组最多生成一条计划，不默认候选首条。优先使用回执中已有的可用性证据选择低影响代表；同一设备供多组复用时只核对一次状态。未选候选保留身份与“状态未核实”，不查询全部资产来证明代表可用。
- 状态只对代表设备取证。使用当前工具真实提供的精确过滤、分页和批量能力；批量结果不含必要证据时，可对缺项代表作定向查询。不要臆造筛选字段，也不要为每个未选候选发单设备查询。大结果按原生工具的截断/落盘提示读取必要内容，不以反复全量读取替代定位；仍缺证据时明确未知，不无限扩展查询。

## 2. 从发现结果生成计划

每条计划用本会话内可辨认的序号关联，包含：型号/动作组、选择依据、真实执行设备及资产身份、动作、按当前合同填写的参数、代表设备状态及观测时间、预期观察、回滚依据和授权停点。主机动作另核对执行点与被管主机的真实 agentId；不能用 IP、设备 ID 或猜测编号代替。

参数只使用合同允许的文档保留地址或明确测试值，不猜真实测试账号、接口、扫描目标或模板 ID。缺少这些必要现场条件时列为待补充，不编造可执行计划。动作禁用、智能体不可执行、无候选、离线或状态未知均保留真实限制，不把未知说成当前可用；只生成计划不发预览、创建、执行或恢复请求。

## 3. 用户要求继续只读验证

- 在同一会话复用上一轮计划，不重新生成一批动作或默换设备、参数；复核已知失效或发生变化的证据。计划实质变化时先回显变化，原授权不能扩大。
- 先按 inputSchema 核对必填项、类型、枚举和目标归属。条件不足、需要用户选择或当前动作没有可信只读预览入口时，给该条明确阻塞，不调用执行接口来“试一下”。
- 对条件齐全且合同支持只读预览的计划，逐条调用固定应急组合，使用原计划动作、设备、参数及适用的顶层 agentId，严格 stop=preview。不要在组合前重复其固定候选、代理、模板发现和校验链。不得使用 create-task 或 execute，不启动扫描、不自动恢复。
- NEEDS_SELECTION 按入口的原生面板规则办理；没有有效选择就把该条保留为待选择，不自行填写确认，也不借其他条目的授权继续此条。
- 每条计划核对真实组合回执；必要时按其原 run_id 读取对应组合结果，不重新发起相同调用。预览阻塞、超时、未知或无预览结果分别记录，不能靠生成命令文本或模型自述判预览成功。

## 4. 汇总与执行边界

逐项列出计划、实际停止阶段、参数检查结果、真实预览结果、证据关联及失败/未验证原因，汇总数量与原计划数一致。预览成功不等于设备已生效，也不能证明未选设备全部可用。没有成功预览时如实说明没有已验证项，不以阻塞说明替代完成。

这些是本会话动态测试输入，不是自动创建了新的 evaluation Case 或 Run。真实执行仍需用户对具体动作、设备和参数的明确授权，并按原请求查询；只读自测不自动获得写入或回滚权限。
