---
name: emergency-action
description: 发现真实动作与执行目标，以应急动作组合按动作真实合同办理；只准备时交付必要事实即结束，其他阶段仅按用户授权推进，并查询原请求。
---

固定多接口调用链使用 `mcp__policy-response-acceptance__emergency_action`；咨询、发现和独立原号查询仍使用 `policy-response` 原始 AISOC 资源与工具。参数以实际动作 schema、inputSchema 和本会话工具目录为准。组合未装载、合同缺失或失败时如实报告停点，不绕过组合逐步重复发现、预览、建任务和执行的固定链；不使用旧 Workbench、本地确认器或自建业务台账。

1. **咨询与发现保持只读。** 问哪些设备有告警时，查询真实事件，保留时间、来源、设备角色和查询范围，不用全部资产冒充异常清单，不认领或研判事件。询问动作能力时读取真实动作目录、目标候选和参数合同，不能把通用动作目录当作某台设备一定支持。复用本会话已选目标与有效结果，已有明确设备时不无故重做身份发现；只有实际歧义或无法查询的必要缺项才询问，不强求用户提供内部标识。
2. **动作、执行点与被管对象分开核对。** 防火墙动作与主机/EDR 动作不能互换。用户已给明确动作和设备时，只在填写 `params` 前按需读取该实际 `actionKey` 的当前 `inputSchema`，已有有效结果直接复用；按原始字段名、类型、必填项和枚举填写，不猜测或翻译字段名，然后直接调用固定组合。目标候选、device-agents、扫描模板、配置与输入字段发现及参数校验交给组合，主 Agent 不在组合前用原始工具重复执行这些固定步骤。EDR 必须由组合核对真实 device-agents 中属于所选执行设备且对应目标主机的 `agentId`；用户已给 ID 也要核对归属，不得用执行设备 IP、deviceId、名称或猜测值代替。非 EDR 动作不强制查询或传 agentId；params 不夹带 agentId、dispatchId 等执行封装字段。动作禁用、智能体不可执行、无合格执行点或参数不支持时保留真实阻塞，不绕过上游限制。
3. **按授权选择 stop，绝不越界。** `stop` 枚举只表示工具总体能力，具体动作能执行或建议哪些阶段，以该动作当前真实合同为准。非扫描动作不得建议 `create-task`。用户只要求准备时，完成后仅交付必要的动作、目标、参数、影响和未执行事实即结束，不主动附加继续操作菜单、下一步选项或另行确认，不询问是否预览、创建任务或执行。总体停点含义：`prepare` 完成真实动作、目标、参数及影响准备后停止，明确尚未下发，不把准备输出说成已保存 SOC 任务；`preview` 取得真实指令渲染与检查结果后停止，不建任务、不执行；`create-task` 只创建真实任务并回读原号，不启动；`execute` 仅在用户明确授权具体动作、对象和参数后按实际合同执行，并查询同一原请求。说明、建议和研判推荐不构成执行授权；参数与授权完整时不机械重复确认。
4. **Nessus 模板与仅创建边界。** 准备 `trigger-scan` 时，由组合读取所选扫描设备的当前模板目录并核对扫描 targets 与 profileId；未指定模板时默认选择当前 `Basic Network Scan` 的实际 ID，不写死历史 profileId，不用模板名称代替 ID，不扩大扫描范围。主 Agent 不在调用组合前重复查询模板、目标候选、配置或输入字段。用户只要求建任务不启动时，必须有当前合同明确支持的独立创建入口；若仅有创建并启动的动作，立即阻塞，不调用该动作，不把预览、方案或受理说成已创建任务。明确这是外部 AISOC 合同缺口，须由外部 AISOC 服务方提供独立仅创建接口；本平台只可在该接口具备后接入，不建议修改本平台来创造外部服务未提供的能力。
5. **按原请求恢复与查询。** 同一执行请求保持原 `requestId`，有原 taskId 或执行记录时按实际恢复合同续办，不重建任务。输入 `requestId` 在未发送或未获 SOC 确认时只是本地输入，不是原请求回执，不能仅据其存在声称有可查记录；是否可查询按真实发送/受理证据及上游查询合同判断。平台 `run_id` 只用于标识和查询组合运行，不能充当 SOC `requestId` 或审批 `workflow instanceId`，也不能由其推导这些标识；SOC 标识按实际合同及真实回执分别核对。受理、审批中和执行中不等于成功或真实设备效果。收到明确的参数校验失败时，依据当前真实契约修正；只有已确认本次调用未产生上游业务写入时才可重试，不能仅凭失败状态推定无写入。已有写入或写入结果未知时先按原号查询与恢复，不重放固定链。超时、断线或结果未知时，先用 `policy-response` 原始查询核对已真实发送的请求/原任务，不换号重发；独立查询不得顺带执行。恢复是用户明确要求的独立反向动作，使用真实反向合同及原结果中的必要标识，不自动补偿。

默认简洁交付真实动作、执行设备、被管目标、参数、当前停止位置、原请求或任务号及证据。严格区分准备、预览、真实创建、受理、阻塞、失败、未知与设备侧实际效果；缺接口、权限不足或外部故障如实报告，不伪造记录、指令、任务号或完成状态，不以说明缺口代替正向任务通过。
