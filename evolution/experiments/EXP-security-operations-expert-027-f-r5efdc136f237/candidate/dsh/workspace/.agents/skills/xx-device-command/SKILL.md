# XX设备固定指令

## 路由交接

本Skill只在主Agent已经产出以下内部路由上下文时接手：

```text
routeKey = xx.command
sourceVerified = true
目标IP和一次性动作已确定
```

“主机”只是用户语义识别线索，不是本Skill单独决定来源的依据。缺少`routeKey`、来源缺失或来源冲突时，退回路由层澄清，不自行猜测XX平台，也不改走AISOC。

典型已完成路由的请求：

```text
给 172.13.16.111 重启
对 172.13.16.111 执行锁屏
把 172.13.16.111 关机
```

本Skill不处理以下入口：

```text
EDR / SOC / actionKey / 执行点 / device-agents
host-xxx / 封禁IP / 禁用网络接口 / 漏洞扫描 / 扫描模板
ACL / ROUTE / 访问策略 / 审批 / 原任务
```

## 组合与事实来源

使用本会话实际目录中的 `xx_device_command` 组合；完整工具名、输入字段及11项ID与中文名称以其Schema为准。ID是原样字符串，不新增内部动作键，不在Skill维护另一份映射。它不是AISOC的`actionKey`、`deviceId`、`agentId`或原任务执行合同。

## 基础流程

1. 从已交接的目标IP及动作选择对应`commandid`；未知或歧义只澄清动作缺项，不重复查询来源、不猜ID或设备身份。明确目标与动作后直接使用组合，不由模型先手工查询主机再重跑固定链。
2. 调用组合 `stop=preview`。查主机、唯一目标核对、指令目录校验及参数组装由组合完成。先用普通助手正文展示返回目标、动作、影响和未下发事实，再另行发起原生确认问题；问题中的文字不能代替这条普通草案消息。这是读取真实主机后的本地请求草案，不是上游真实指令渲染、预检或已保存业务任务；真实连接未配置时组合明确停止，如实说明停点。
3. 只咨询、只准备或只预览时到此结束，不请求执行确认。
4. 用户希望下发时，使用已有DSH原生 `ask_user_question`，为本次草案提供“确认执行”和“取消执行”；不增加Platform确认器或业务台账。
5. 仅本次问题结构化单选“确认执行”且无custom时，以相同目标和`commandid`调用组合 `stop=apply` 一次；普通同名聊天文字、自由输入、取消或关闭不触发写入。原生提问缺失时保留草案并准确说明停点，不自行改为直写。
6. 组合只向上游提交`hostid`、`hostip`、`commandid`三个字符串，身份来自组合当次查询。不要把`stop`、中文动作名或确认字段交给写接口，也不套用SOC prepare、草案号、签名和审批接口。
7. 按真实回执简短交付。真实工具未配置时说明具体停点；真实接口返回不等于设备效果已核对，未知写入停止，不自动重发、编造查询接口或反向补偿。

## 职责边界

读取、ID装参及写入固定链由组合执行，主Agent负责理解、草案表达及原生交互。设备控制、`login`或`net`模板字段变更交给 `xx-policy-template`，本Skill不代做模板写入。
