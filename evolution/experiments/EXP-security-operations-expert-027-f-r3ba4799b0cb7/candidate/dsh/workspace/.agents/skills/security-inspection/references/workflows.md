# 查询与执行的选择

按用户要得到的结果选择已有能力，不按巡检分类逐个建立或启动组合。简单事实查询由 Skill 组织现有工具；需要语义判断的下一步由助手选择；固定的数据衔接、分页、覆盖判定、汇总与可确定恢复由现有组合执行。单台也可能需要完整检查，多台列表也可能一次原始查询就足够，不能以设备数或接口数代替判断。

## 简单流程

| 用户任务 | 办理方式与结束位置 |
|---|---|
| 查询有哪些巡检项、介绍区别、预览范围 | 读取当前已发现工具描述与 Schema，说明可检查什么、必要输入及限制；不启动运行。 |
| 查询设备、单台在线状态、已有漏洞记录或已知两端的路径事实 | 由主助手直接选择当前已发现的 SOC 只读工具，按实际 Schema 读取资产、在线证据、已有漏洞或路径；保留对象、来源、时间、分页与缺失信息，读取足够事实即可结束，不委派故障子助手、不创建诊断或巡检运行。需要多证据关联和原因分析时才转入 [fault-analysis 公开入口](../../fault-analysis/SKILL.md)。 |
| 读取已经完成或仍在执行的巡检、明细、报告 | 沿用真实运行标识，按主入口的“结果与报告”读取原运行；查询工具不是重新执行巡检。 |
| 查询、创建或删除周期任务 | 按实际发现的原生 Schedule 工具办理；创建保留用户指定的巡检内容、范围和周期，仅登记到期意图。登记成功不能声称巡检已执行，也不为登记任务先启动一次巡检。 |
| 解释异常、比较已有事实、决定接下来检查什么 | 使用已经取得的证据作语义判断，只补充当前判断需要的读取；明确事实缺口。用户进一步要求完整检查时再选择相应组合，不把咨询升级为全范围执行。 |

先核对实际工具可见性与 Schema。主助手与故障子角色复用现有 SOC 只读能力，不能把配置中的工具名当作已发现或已调用。不能枚举设备时，不声称没有设备；不能读取最新基线报告等单项事实时，说明缺少该只读能力，不为绕过缺口启动完整巡检，不猜工具名或改用 Shell/HTTP 访问上游。

## 完整检查的组合边界

先核对上游是否已经完整提供所需结果，已有能力直接复用；上游完成的聚合、判定和证据加工不能重复计为组合贡献。下表说明完整检查的选择条件，不证明每个组合已经比原始工具更快。是否保留、合并或撤销，仍须按相同输入比较结果完整性、模型往返、上游请求与耗时；不得用既有数量或成功运行代替必要性判断。

| 组合 | 应使用它的任务 | 不需要它的任务 |
|---|---|---|
| inspection-baseline | 关联最新报告与 readiness，校验对象、模板和检查项覆盖，保留部分失败并汇总。 | 只读取一份已有基线报告；前提是实际可用的只读工具能提供它。 |
| inspection-vulnerabilities | 读取登记父子对象、逐对象漏洞及来源，去重关联并判定覆盖情况、汇总报告。 | 只查询已知资产当前已有的漏洞记录；不据空记录推断所有子对象均无漏洞。 |
| inspection-reachability | 根据启用规则生成检查对，衔接路径与逐跳 ACL、核对覆盖并按规则汇总；地址转换证据不足时保留未知。 | 查看一个已知路径或连接事实；存在路径本身不证明完整策略可达。 |
| inspection-routine | 用户要求完整常规巡检，内部汇总状态证据，固定复用基线和可达性检查，共享范围与额度并汇总。 | 询问常规巡检包括什么，或只需要其中一项已有事实。 |
| inspection-deep | 用户要求完整深度巡检，固定复用常规检查与漏洞检查，避免重复执行并汇总。 | 咨询深度巡检区别，或只读取某一类事实、已有深度报告。 |

状态查询直接使用原始只读工具，按在线证据的来源、观测时间和有效窗口解释；证据缺失或矛盾时保留未知，不推断故障原因。完整常规巡检的状态部分由内部节点复用同次冻结资产，不另发布状态组合。当前保留的五项组合分别承担跨报告关联、父子资产遍历、路径与 ACL 衔接或这些检查的固定汇总；实际发现的工具目录仍以实例回执为准。
