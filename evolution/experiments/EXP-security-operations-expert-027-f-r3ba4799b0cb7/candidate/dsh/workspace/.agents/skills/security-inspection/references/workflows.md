# 查询与执行的选择

简单已有事实查询使用当前可见SOC只读工具；完整巡检使用已发布组合；读取已有结果沿用真实Run；周期任务使用原生Schedule。咨询、预览、否定执行不创建Run。不得通过Shell或HTTP绕过工具，不猜工具名、节点或资源URI。需要故障分析时交接[fault-analysis公开入口](../../fault-analysis/SKILL.md)，不在巡检中自动诊断。

## 完整巡检

| 组合 | 用途 |
|---|---|
| inspection-baseline | 读取报告和readiness，核对对象、模板与结果，分别保留未绑定模板、未采集数据和读取失败。 |
| inspection-vulnerabilities | 读取资产及真实直接子资产的已有漏洞，校验关系、完整读取后汇总。 |
| inspection-reachability | 根据启用规则生成检查对，读取路径及ACL，保留缺分层、无完整检查对等缺口。 |
| inspection-routine | 共享冻结范围，汇总SOC状态、基线与可达性。 |
| inspection-deep | 复用常规结果并汇总已有漏洞，不重复执行常规检查。 |

## SOC判据与聊天统计

本节为本次用户批准的最终判据，适用于常规、深度、单项结果及聊天；旧Run不重判、不重绘。

- 默认SOC返回为最新数据。`online=offline`直接显示“离线”，判为异常；`online=online`直接显示“在线”，判为正常。不得因lastSeenAt为空、无采集心跳、时间格式或本端证据冲突改为unknown。保留SOC原状态、来源与时间，不推断离线原因。`online=unknown`精确显示“SOC未采集到状态数据”，不虚构在线或离线。
- SOC明确`NO_TEMPLATE`显示“设备未绑定基线模板”，包括templateId=null的明确组合；`NO_DATA`精确显示“SOC未采集到基线数据”。两者分开按reason统计，均不作基线通过。网络、权限、解析和对象不一致等失败独立保留，不能伪造未绑定或未采集原因。不擅自绑定模板或补采。
- 已有漏洞成功、完整读取且为空时显示“没有漏洞”，计为正常；成功有记录时按已有漏洞异常呈现。不得再用“空返回不能说明无漏洞”否定完整空结果。网络、权限、解析、子资产分页或任何读取不完整仍为失败/未完成，不能显示没有漏洞；仅查询已有漏洞，不启动扫描。保留来源及时间。
- `item_count`及执行completed只说明处理/读取数量，不代表全部在线或全部有明确业务结论。明确判定数为normal+abnormal，unknown、failed、not_applicable分列；failed=0不证明完整，执行完成与业务incomplete分开。
- sources引用条目数、按assetId去重的资产来源数、返回漏洞记录数及归并findings数分别说明。引用条目不能当成漏洞数或唯一资产数，跨宿主重复的来源/记录不能直接相加为唯一漏洞总数。计数仅用该Run实际证据。
- 宿主/直接子资产关系仅采用同次已存hostAssetId或明确关系来源；缺失时不按名称、IP、排序或被汇总位置猜归属。先读同Run已有明细补证；仍缺就说关系来源未保留，不能用当前SOC补写旧快照或新Run冒充旧结果。
- 真正读取失败、未执行、主体/证据冲突或必需证据缺失才列缺口；完整成功读取/匹配后无适用对象、无跨地址检查对是范围结论，不归咎预置规则、不判规则非法、不要求补图层或扫描。LAYER_NOT_FOUND 只有在确实缺少判定所需图层/证据时才保留为读取缺口。

聊天沿主入口顺序输出30秒速读、统计、异常项、证据与原报告。数量、单位和比例仅加粗；明确异常描述才粗体红色，不加红色圆点或警报emoji。未知、未完成及基线缺模板不染异常红。未验证聊天红字能力时保留粗体，不输出无效HTML/CSS，不声称红字已经生效。只用真实Run/明细/产物链接，不为下载重跑。工程修复仅影响后续固定版本和新Run，旧报告保留原字节。
