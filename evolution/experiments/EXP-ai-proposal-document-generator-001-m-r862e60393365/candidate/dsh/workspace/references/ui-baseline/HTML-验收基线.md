# 方案文档生成工具｜HTML 严格验收基线

## 1. 验收原则

本材料包以 `方案文档生成工具-静态验收原型.html` 为唯一可执行验收基线。验收人员必须按照 HTML 中的真实 DOM、`data-testid`、`data-acceptance`、`ui-acceptance-contract`、默认状态和交互行为进行验收。

本文件、测试清单和映射文档只解释验收意图；如果文字说明与 HTML 的实际结构或行为不一致，以 HTML 为准。材料包不依赖效果图片，也不把截图作为通过条件。

## 2. 文件与唯一职责

| 文件 | 用途 | 是否为通过依据 |
|---|---|---|
| `方案文档生成工具-静态验收原型.html` | 可执行静态原型、交互和默认状态 | 是，唯一执行基线 |

## 4. 核心默认状态

HTML 初始加载后必须满足：

- 文档模式激活；
- 右侧“证据”面板激活；
- 左侧章节“03 总体架构”激活；
- 顶部覆盖率为 86%；
- 章节质量分为 86%；
- 至少显示 2 个待确认主张；
- 发布门禁为阻断状态；
- 文档标题为“3.2 总体架构与建设思路”；
- 文档内容以中文为主；
- 纸张占满中央编辑区可用宽度；
- 图表索引位于正文前部；
- 图 3-1、图 3-2、表 3-1 都有真实正文对象和锚点；
- 架构图和流程图加载后直接显示图形，不显示原始 Mermaid 代码替代图形；
- Mermaid 图形外层无边框、无卡片阴影，节点尺寸根据节点文本自适应；
- 顶部和发布页面只提供 Markdown、DOCX 下载入口。

## 5. Mermaid 验收标准

### 5.1 源码保留

每个图形必须保留 `pre.mermaid-source` 源码，源码可以通过“查看 Mermaid 源码”展开查看。源码属于文档资产，不能只保留最终 SVG。

### 5.2 直接渲染

页面加载后，`pre.mermaid-source` 应被渲染为 `.mermaid-shell`，`.mermaid-shell` 内必须存在 `svg`、节点矩形、节点文字和连线。图形不能要求联网或加载外部 Mermaid CDN。

### 5.3 无边框模式

验收时检查：

- `.mermaid-shell` 没有可见边框；
- `.mermaid-shell` 没有卡片背景；
- 文档中的 `.document-mermaid` 没有外层卡片边框和阴影；
- 图注和源码折叠区可以保留文本分隔线，但不能给图形本身增加边框。

### 5.5 字号一致性

Mermaid 图中的文字必须与正文文字保持接近的视觉尺寸：

- 默认正文基准约为 15px；
- Mermaid 节点文字基准约为 15px；
- 在同一视口下，Mermaid 节点文字与正文文字的视觉差异建议不超过 ±2px；
- 不能因为竖向图的 `viewBox` 过窄而把整张图放大，导致节点文字明显大于正文；
- 图形应根据实际容器宽度建立画布，不能用过小的固定画布宽度触发异常缩放；
- 如果图形内容过宽，可以整体缩小，但不得出现单个 Mermaid 节点文字远大于正文的情况。


节点宽度和高度必须由节点文字计算，不能所有节点固定为同一个尺寸。长中文节点应自动换行，渲染为多个 `<tspan>`；节点文字不能溢出矩形。连线应从节点边缘出入，不能从节点中心穿过节点。

## 6. 图表索引验收标准

- `[data-testid="document-indexes"]` 必须存在；
- 必须同时存在“图索引”和“表索引”；
- 图索引至少列出图 3-1、图 3-2；
- 表索引至少列出表 3-1；
- `href="#fig-1"` 能定位到图 3-1；
- `href="#fig-2"` 能定位到图 3-2；
- `href="#tbl-1"` 能定位到表 3-1；
- 正文至少有一次对图 3-2 和表 3-1 的引用；
- 图注使用 `figcaption`，表题使用表题元素或等效标记；
- 索引名称、图题、表题和正文引用使用中文优先。

## 7. Markdown 验收标准

- 点击工具栏“Markdown”后，`markdown-workbench` 可见；
- 左侧 `markdown-source` 是可编辑文本区；
- 右侧 `markdown-preview` 显示渲染结果；
- 修改 Markdown 后预览同步更新；
- 默认 Markdown 内容包含中文标题、图表索引、两个 Mermaid 图块和一张 Markdown 表格；
- Markdown 表格渲染为 `.md-table`；
- Mermaid 代码块渲染为 `.mermaid-shell`；
- 预览中仍可展开“查看 Mermaid 源码”。

## 8. 其他核心页面

左侧导航必须能够在同一 HTML 中切换以下视图，并在 `view-host` 中出现对应 `data-view`：

`overview`、`materials`、`requirements`、`design`、`review`、`evidence-library`、`ai`、`compare`、`publish`、`eval`。

页面切换不应刷新浏览器、不应依赖后端、不应依赖外部网络。

## 9. 选中文本 AI 浮框

- 文档标题和正文段落支持文本选择；
- 选择文本后浮框进入 `.show` 状态；
- 浮框显示实际选中文本预览；
- 快捷指令可以写入输入框；
- 自定义指令可以提交；
- 提交后显示反馈 Toast；
- 浮框在视口边界内自动调整位置。

## 10. 下载验收

允许的下载文件只有：

- `方案文档-v0.6.md`，MIME 为 `text/markdown;charset=utf-8`；
- `方案文档-v0.6.docx`，MIME 为 `application/vnd.openxmlformats-officedocument.wordprocessingml.document`。

不允许出现 PDF、ZIP、发布清单 JSON 或其他导出按钮。整包 ZIP 是验收材料包本身，不属于 HTML 的产品导出功能。

## 12. 边界

这是静态 HTML 验收原型，不代表真实模型、真实材料解析、真实权限或真实文档生成服务已经完成。验收只判断 HTML 中明确实现的结构和交互；正式产品需要在此基线上接入真实后端，并保留相同的状态语义、图表索引、源码保存和下载约束。

## 13. 开源复用优先

正式产品实现必须优先站在成熟开源成果之上，减少重复造轮子。编辑区、Markdown 编辑与渲染、Mermaid、表格、差异对照、文件解析、DOCX 生成和下载等能力，应先检索并评估成熟开源组件，再决定是否自行实现。

验收时必须能说明：

- 组件名称、版本和来源；
- 许可证及商用边界；
- 复用的功能范围；
- 自研改造范围；
- 安全、权限、隔离和数据处理边界；
- 升级、替换和供应链风险策略。

静态 HTML 为了离线验收可以使用内嵌渲染示意，但正式产品不能以静态示意替代对成熟开源编辑器、Markdown 渲染器、Mermaid 渲染器和 DOCX 生成组件的选型评估。
