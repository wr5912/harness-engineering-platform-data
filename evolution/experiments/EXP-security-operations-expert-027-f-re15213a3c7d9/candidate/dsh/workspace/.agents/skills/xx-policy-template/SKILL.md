# XX设备策略模板

## 路由交接与事实来源

本Skill只在主Agent已经产出以下内部路由上下文时接手：

```text
routeKey = xx.policy
sourceVerified = true
目标IP和模板变更意图已确定
```

缺少`routeKey`、来源缺失或来源冲突时，退回路由层澄清，不自行猜测XX平台，也不改走AISOC `policy_change`。来源查询只发生在路由层，本Skill不重复查询来源。

使用本会话实际目录中的 `xx_device_policy` 组合，以真实完整工具名和inputSchema为准。它与AISOC的 `policy_change` 是不同合同，不调用旧Platform、prepare/签名确认器、审批或本地业务台账。组合缺失或失败时说明实际停点，不让模型改为逐步重跑固定读写链。

模板字段、允许值及明确的业务含义以组合工具Schema和当次返回为唯一事实源，不在Skill维护另一份表。模板顶层是hostid、hostip及“设备控制”、login、net三个Map，所有配置值为字符串，字段原名（包括osuer、proctocol）不能翻译或修正。login目前只有字段和允许编号，不猜编号的业务含义或时间单位；用户已给字段及编号时直接使用，只澄清真实缺项。

## 基础流程

1. 使用已交接的目标IP和本次修改意图，将用户语义转换为工具支持的delta。只列本次修改字段，但调用前须按当前inputSchema逐层完整填写required；必填Map即使未修改也显式传{}，省略不等于空对象。不加入commandid、版本、操作号或确认标志。
2. 调用组合 `stop=preview`。固定的读模板、取得hostid、字段校验及五字段实体组装由组合负责；主Agent不在前面重复查主机。只查看时允许空delta，到结果后结束。
3. 用正常助手消息展示目标、配置项、原值到新值及尚未下发。这里preview是读取后的本地参数/差异草案，不是上游真实渲染、预检、已保存草稿或设备效果。
4. 用户要求只读或只准备时停止，不请求执行确认。用户希望下发时，复用已装载的DSH原生 `ask_user_question`，针对本次草案提供“确认执行”和“取消执行”。不创建替代面板、确认控制器、签名或固定普通聊天确认词。
5. 仅本次原生问题的结构化答案单选“确认执行”且无custom时，以本次相同目标和delta调用组合 `stop=apply` 一次。普通同名文字、取消、关闭、自由输入均不触发写入。原生提问不可用时保留草案并说明缺口，不绕行写入。
6. 写实体装配、只读定位和一次提交均由组合完成。按真实回执区分接口返回与设备效果；未配置真实工具时说明停点。取消明确未下发。写入超时、断线或结果未知时停止，不自动重发或补偿，不虚构原任务查询能力。

当前组合已切换为真实上游接入骨架：真实连接、工具名和回执合同未配置时明确停止，不回退Mock。暂不处理后台模板新建、合并、持久化应用、并发版本或复杂回执；真实写入成功与设备效果仍须按内网合同分别核对。
