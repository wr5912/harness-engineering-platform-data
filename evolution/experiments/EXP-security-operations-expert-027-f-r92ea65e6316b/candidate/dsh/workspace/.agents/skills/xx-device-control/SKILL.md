# XX设备固定指令（开发Mock）

查询、草案展示、DSH原生确认、提交及回执解释复用同一流程，按已选服务使用对应的MCP读写工具；不同MCP来源不另设互斥业务域。本Skill负责已选XX设备Mock服务的调用合同；SOC来源特有的草案号、签名及提交仍由原受信组件处理，不拿XX参数调用SOC专用接口或编造SOC操作号。所有XX结果必须说明是开发模拟，不会操作真实设备。工具或原生提问能力缺失时报告缺口，不猜工具、不改用其他来源，不用Shell或直接HTTP代替。

## 名称到指令ID

唯一映射资产是同一Candidate的 `dsh/managed/xx-device-command-map.json`，结构严格为ID到中文名称，共11项。ID是原样保留的字符串，支持UUID样式，不转数字、不改变大小写或补零；当前开发占位ID不代表现场真实编号。MCP服务从这份资产生成工具描述及参数定义；按当次真实工具目录中的说明理解用户动作并取得ID，不维护另一份表、不引入内部动作键、不猜测ID。动作表达不明确或不在目录中时先澄清，不能选相近动作凑数。

## 查询与草案

1. 提取用户明确指定的一个目标IP，调用已选XX设备服务的 `lookup_host` 读工具，仅传 `hostIp`。缺目标时先询问，不擅自选主机。
2. 只有正常查询回执明确无设备时，提示“当前 IP 无对应主机设备”并结束；查询失败要说明查询失败，不能冒充无设备。多匹配时先请用户选择。`hostId` 和设备名称只能取真实Mock回执，不能生成或猜测。
3. 有唯一设备且动作明确时，确定最终写入三字段 `hostid`、`hostip`、`commandid`，三者全部为字符串：前两项原样取本次查询的hostId、hostIp，commandid原样取指令映射，作为本次草案。用正常助手消息展示“目标设备：名称（IP）”“指令动作：中文名称”，加“开发模拟，未下发”。不创建额外操作台账，不编造上游未返回的操作号。确认之前不能调用写工具。

## 原生确认与取消

用户仅要求查询时交付查询结果；明确只准备草案、不发起确认时，展示草案后结束，不调用提问或写工具。只有本轮已要求推进到执行确认，才继续下述交互。

通过当前实际可用的DSH原生提问工具询问“是否立即执行这条模拟指令？”，提供“确认执行”“取消执行”和原生自由输入，沿用原生展示和交互，不实现替代面板或消息/执行循环。

只有原生回执 `answers` 中与本次问题ID对应的一项 `selected` 恰为单选“确认执行”、且没有自由输入 `custom`，才调用已选服务的 `send_command` 写工具；参数严格为草案中的 `hostid`、`hostip`、`commandid` 三个小写字段且全部为字符串，不使用旧camelCase写字段，不增加确认标志或内部动作键，不换参数。取消、跳过、关闭或自由输入均不授权写入。用户要求变更目标或动作时先废弃旧草案，按新意图重新查询、展示及确认。

## 模拟回执

只按实际写工具回执报告“模拟下发成功”“模拟下发失败”“模拟请求已受理，不代表执行完成”或“提交结果待核实”，不得声称真实设备已重启、关机或已生效。不新增第三个结果查询接口。写入超时或结果未知时不自动重发。已取消、已提交或已完成的这次草案不能因重复的“确认执行”再次下发；用户发起新的完整请求时再走新一轮查询与确认。
