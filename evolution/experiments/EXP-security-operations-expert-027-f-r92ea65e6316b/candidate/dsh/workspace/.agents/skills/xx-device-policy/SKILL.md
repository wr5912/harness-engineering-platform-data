# XX设备策略模板基础配置

## 范围与工具

本期只实现开发Mock基础闭环：读取模板 → 识别并修改目标配置项 → 展示草案 → DSH原生确认 → 写入参数 → 说明模拟下发成功。不处理并发、模板版本、后台新建模板或应用设备、复杂回执及效果验证。

使用当前已选XX策略模板来源目录中的 `read_policy_template` 与 `write_policy_template`，以实际发现的完整工具名和Schema为准。它们是另两个工具，不调用指令系列的lookup_host、send_command，不使用11项指令ID映射，也不把设备配置项转换成“网络连通/网络隔离”指令。不调用旧SOC策略prepare、签名或提交接口。

接口Schema、占位字段、取值含义由本Candidate的策略Mock工具定义；模拟设备和模板数据由 `dsh/managed/xx-device-policy-fixtures.json` 维护。按工具目录和本次读取结果定位目标map与字段，不再维护一份字段映射表。当前三个map各放一个占位项，真实格式后续由用户确定。工具缺失时说明不能继续，不猜工具、不用Shell/HTTP绕行。

## 基础步骤

1. 从用户输入取得设备IP及明确的配置意图。对于启用、关闭、禁用无线网卡等配置项请求使用本Skill；重启、关机、锁屏等固定指令仍交给其原有Skill。
2. 调用读模板工具，以本次回执中的hostid、hostip及三个map为事实来源。未找到设备或读取失败时结束，不虚构模板。
3. 依工具定义理解目标字段的值，将用户意图转换为该字段的新值。只构造本次变更，不回传整个原模板：写实体严格保留 `hostid`、`hostip`、`map1`、`map2`、`map3` 五个字段；前两项为本次读取的字符串，仅目标map填入本次修改的字段与值，其余map为 `{}`。不增加commandid、版本号、操作号或确认标志。
4. 先用正常助手消息展示“目标设备IP、配置项、原值含义 → 新值含义、开发模拟/尚未下发”。不要把草案当成已执行。用户仅要求读取或只准备时在此结束，不发起确认、不写入。
5. 通过既有DSH原生 `ask_user_question` 为本次草案提供“确认执行”和“取消执行”两个单选项，保留原生自由输入；不实现替代面板或自定义确认控制器。确认之前不能调用写工具。
6. 只有工具返回本次问题的真实结构化答案，且该问题的selected恰好为单项“确认执行”、没有custom自由输入时，才将本次草案五字段原样调用写模板工具一次。普通聊天文字不是原生选择；取消、跳过、关闭、自由输入均不写入。
7. 写工具返回成功时简短说明“模拟下发成功”，本期不解释后台如何新增模板或应用，也不声称真实无线网卡已生效。取消时说明未下发，不调用其他来源写入。
