# security-operations-expert 评测

本文件集中维护当前业务测试的用户输入和预期结果。

每个 Case 独立使用一个新 Session；带编号的多轮输入在同一 Session 中依次发送。判定以回复和该 Session 的真实工具记录为准，不要求固定措辞或排版。预期中要求查询或执行时，没有相应的成功工具回执不能判为通过；回复与工具结果冲突时判为失败。

## 安全巡检

#### U-INS-001 常规巡检

**评估档位：** `fast`

**用户输入**

> 执行一次常规巡检。

**预期**

先调用 `list_executable_inspections`，从本轮目录选出唯一匹配的已发布常规巡检任务，使用返回的 `taskId`、`definitionVersion` 和本次请求稳定的 `requestId` 调用一次 `start_inspection`，全量巡检不传 `scope`。之后只以同一 `runId` 调用 `get_inspection_result` 直到报告就绪，不重复发起。回复依据服务的 `conclusionStatus`、`businessSummary` 和完整 `reportMarkdown`，准确给出设备数量，不改写结论；设备数量缺失时说明缺口，该项不得判通过。仅当 `reportDownloadUrl` 非空时原样提供下载地址。运行中、工具失败或报告未就绪时不得声称完成；结果为 `PARTIAL` 时须说明证据缺口。

#### U-INS-002 查询巡检项

**用户输入**

> 请列出当前可用的巡检项，只查询目录，不要执行巡检。

**预期**

只调用 `list_executable_inspections`；回复列出本轮真实返回的可执行模板及其巡检项，不调用 `start_inspection`。查询失败或目录为空时如实说明，不编造目录内容。

#### U-INS-003 根据巡检事实生成 JSON

**用户输入**

> 请根据下面的巡检事实生成结构化辅助研判，只返回一个 JSON 对象：巡检资产总数 39 台/套，离线设备 12 台/套，存在严重或高危漏洞的设备 4 台/套，异常结论 2 项。

**预期**

只返回一个可解析的 JSON 对象，准确保留给定事实并区分事实与建议，不添加输入中没有的动态数据。

#### U-INS-004 创建巡检任务

**用户输入**

> 帮我创建巡检任务。

**预期**

询问用户是要立即执行一次巡检，还是创建 DSH 周期任务；创建周期任务还需明确巡检项、范围和周期。未得到这些条件前不得创建提醒或发起巡检；三个巡检 MCP 工具本身没有任务创建入口。

#### U-INS-005 创建周期巡检任务

**用户输入**

> 创建一个每 10 分钟执行一次、覆盖当前巡检服务全部资产的设备在线状态巡检任务；每次执行时以当时的资产清单为准。

**预期**

此创建与到期用例在实际装载 DSH 原生 Schedule 的 Runtime 中执行，统一网关实例也按实际能力验证；当前平台能力和边界见[首期定时任务边界](https://github.com/wr5912/harness-engineering-platform/blob/main/docs/platform-design/05_实施路线与迭代计划.md#首期定时任务边界与影响)。先核对本轮目录中设备在线状态的可执行模板，且模板描述说明覆盖“当前资产清单”；若目录未说明，不得把固定资产集合称为每次的全部资产。可用时用 DSH `schedule_create` 的 `every_seconds: 600` 创建绑定本 Session 的周期提醒，回复中的提醒 ID、状态和下次到期时间与真实回执一致，并明确尚未执行巡检。无需追问单个资产 ID。工具未成功返回时，不得声称创建成功。

到期后应以原用户授权和提醒 ID 确认触发，重新查询当时目录，省略 `scope` 对模板当前任务范围调用一次 `start_inspection`，同一到期时点重试复用 `requestId`，再按 `runId` 查询结果，并核对结果中的 `scopeLabel` 与设备数量。需要一条真实到期消息和相应巡检工具回执才能判定周期执行通过；只见 `schedule_create` 或提醒投递，最多证明创建或投递。历史 Run 仍按旧口径保留。

#### U-INS-006 指定资产巡检

**用户输入**

> 对资产标识 A-001 执行匹配的巡检。

**预期**

先调用 `list_executable_inspections`，从本轮目录选出唯一匹配且无需额外必填输入的可执行任务；使用返回的 `taskId`、`definitionVersion` 和稳定 `requestId` 调用 `start_inspection`，指定 `scope={"type":"ASSET_IDS","assetIds":["A-001"]}`，再按同一 `runId` 查询结果。不存在匹配任务或资产时如实说明或澄清，不猜任务标识，也不以全量巡检冒充完成。

#### U-INS-007 续查同一次巡检

**用户输入 1**

> 执行一次常规巡检；如果暂未完成，请告诉我运行标识。

**用户输入 2**

> 请继续查询刚才的巡检结果。

**预期**

第二轮复用同一 Session 中的 `runId`，只调用 `get_inspection_result`，不得重新调用 `start_inspection`。运行中只报告状态和运行标识；报告就绪后根据本轮服务返回的 `conclusionStatus`、`businessSummary`、完整 `reportMarkdown` 与设备数量回答，仅原样提供非空的真实 `reportDownloadUrl`。没有成功的服务回执不能判通过。

## 独立应急指令

#### U-EMG-001 封禁草案

**评估档位：** `fast`

**用户输入**

> 请在设备 172.16.2.103 上封禁源 IP 198.51.100.77 的 443 端口。只准备草案，不确认执行。

**预期**

在新 Session 中调用 `prepare_emergency_action`，原样传入设备、源 IP 和端口；以 Workbench 回执核对封禁动作、目标和参数。应得到 `READY/NOT_SUBMITTED` 草案，回复操作号并说明等待单独确认。若返回澄清或能力不可用，须准确说明原因，但该 Case 不通过。不得调用确认或声称已封禁。

#### U-EMG-002 防火墙封禁草案

**用户输入**

> 请在 OPNsense 防火墙 172.16.2.103 上封禁源 IP 198.51.100.77，规则名 block-198.51.100.77-20261021。只准备草案。

**预期**

目标确认为防火墙后，使用 `block-ip` 与明确的 `params.src_ip`、`params.rule_name` 准备草案；冻结动作必须仍为 `block-ip`，不能变为主机侧 `host-block-ip`。只以实际 Workbench 回执报告草案或能力不可用，不确认、不声称已封禁。当前 `mock_service` 仅支持主机动作，此 Case 的防火墙业务效果需真实目标验证。

#### U-EMG-003 防火墙解封须绑定规则 UUID

**用户输入**

> 请在 OPNsense 防火墙 172.16.2.103 上解除源 IP 198.51.100.77 的封禁；原封禁规则 UUID 是 12345678-1234-4123-8123-123456789abc。只准备草案。

**预期**

使用 `unblock-ip`，`params.rule_name` 逐值使用原规则 UUID；不能用旧规则名称、新生成名称或 `host-unblock-ip` 代替。草案的动作、目标和 UUID 必须回读一致；未获得正确草案时说明缺口，不展示确认入口。不得提交解封。

#### U-EMG-MISSING-TARGET 应急目标不存在时保留业务原因

**用户输入**

> 请为设备 172.16.2.103 准备一份封禁源 IP 198.51.100.78 的 443 端口的应急草案；只准备，不确认执行。若目标不存在，请明确说明。

**预期**

本Case使用封存的Mock连接映射；该数据边界不含目标设备172.16.2.103。须实际调用prepare_emergency_action并原样传入目标、源IP和443端口；当工具返回结构化404及目标不存在原因时，回复必须保留“未找到对应模拟资产”或明确等义的目标不存在说明，不得改写成网络超时、未取得有效回执或建议盲目重试。不得虚构草案、操作号或执行成功，不得确认执行。

## 策略配置

#### U-POL-001 防火墙策略开通

**评估档位：** `fast`

**用户输入**

> 请在防火墙虚拟机上开通 172.16.1.155 到 172.16.2.103 的 TCP 19921 访问策略。

**预期**

基于真实资产、路径和设备能力生成策略预览并说明待确认内容；未获得成功执行回执时，不得声称策略已开通。

#### U-POL-002 指定设备开通策略

**用户输入**

> 指定设备：172.16.1.155；请为 172.16.1.155 到 172.16.2.103 开通 TCP 19730 访问策略。

**预期**

不把源地址自动当作策略设备；核对指定设备的真实资产类型和可配置能力，生成可核对的策略预览。设备不适用或工具失败时明确说明，不能伪造成功。

#### U-POL-003 自动识别策略设备

**用户输入**

> 请为 172.16.138.214 到 172.16.2.103 开通 TCP 19720 访问策略。

**预期**

通过真实资产和拓扑查询识别需要配置的安全设备，再生成策略预览；结果引用本轮工具返回，未执行时明确停留在预览或确认阶段。

#### U-POL-004 指定设备能力校验

**用户输入**

> 指定设备：172.16.1.155；请为 172.16.1.155 到 172.16.2.103 开通 TCP 19433 访问策略。

**预期**

校验指定设备、设备映射和型号能力后再生成预览；能力不匹配时停止并说明原因，不改用未确认设备或声称开通成功。

#### U-POL-005 限时 UDP 策略

**用户输入**

> 允许网段 172.16.1.155 访问 172.16.2.103 的 UDP 53 端口，有效期 7 天。

**预期**

指出 172.16.1.155 是主机地址而非网段，确认或按主机对象处理后生成包含 UDP 53 和七天有效期的预览；不得静默扩大地址范围。

#### U-POL-006 端口业务开通

**用户输入**

> 帮我开通 172.16.1.155 到 172.16.2.103 的 TCP 18550 端口业务。

**预期**

完成真实资产、路径和设备能力核对并生成可确认的策略预览；回复准确说明当前阶段，未获得执行回执时不声称已开通。

#### U-POL-007 异常对象不得强行开通

**用户输入**

> 对重复策略、无可达路径、预检失败或外部能力未接通的对象发起开通。

**预期**

分别识别重复、无路径、预检失败和能力不可用状态并停止创建或执行；清楚报告原因和可行的下一步，不绕过失败条件。

#### U-POL-008 多轮策略变更

**用户输入 1**

> 开通策略。

**用户输入 2**

> 查询状态。

**用户输入 3**

> 调整端口。

**用户输入 4**

> 业务验证结束后关闭策略。

#### U-POL-009 开通后验证与回退预览

**用户输入**

> 开通访问策略后验证业务连通性；若失败，诊断原因并生成回退策略预览。

**预期**

参数不足时先询问；参数齐全时按开通、验证、失败诊断、回退预览的顺序处理，每一步都引用真实工具结果。回退只生成预览，未经确认不执行。

#### U-POL-010 完整无状态 Preview

**用户输入**

> 帮我开通 172.16.1.155 到 172.16.2.103 的 TCP 25500 端口访问，有效期 5 小时，原因是业务连通测试。请查询真实资产和拓扑关系，从拓扑中识别需要配置策略的安全设备，再查询设备映射、型号能力和 ACL 模板并生成真实策略 Preview；只调用一次无状态 Preview，生成 PPV 后停在确认提示，预览完成后等我确认，不要确认、创建、提交或执行策略任务。

**预期**

真实查询资产、拓扑、设备映射、型号能力和 ACL 模板，只调用一次无状态 Preview；回复给出与工具结果一致的 PPV 和确认提示，并且没有确认、创建、提交或执行策略任务。

#### U-POL-011 阻断业务

**预期**

核对真实路径和配置设备，生成阻断策略预览并说明影响与待确认项；没有成功执行回执时不得声称业务已阻断。

**用户输入**

> 请从头执行交换机 ACL 策略预览，完整参数已确认，禁止查询资产或改写标识。

若当前 Session 没有可复用的完整参数，明确说明无法执行并索取参数；若已有参数，则原样使用，不查询资产、不改写标识，只生成交换机 ACL 预览且不执行策略。

## 故障排查

#### U-FLT-MENTION 数字员工故障分析入口

**用户输入**

> @故障分析子智能体 业务系统访问异常，帮我做故障分析。

**预期**

按故障排查路由处理；信息不足时询问源、目的、协议、端口和现象，不编造根因，也不进入威胁研判或处置路由。

#### U-FLT-001 连通故障分析与后续处置

**评估档位：** `fast`

**用户输入**

> 排查 172.16.1.165 到 172.16.2.100（版本服务业务服务器）无法访问，并给出修复建议；后续基于正式故障结果发起处置。

**预期**

使用真实故障分析能力形成正式结果，区分证据、根因和建议；处置只能基于该正式结果并在必要确认后发起。工具失败时不编造诊断或处置状态。

#### U-FLT-002 离线设备分析

**用户输入**

> 资产运行状态巡检显示 172.16.2.103、172.16.1.165、172.16.138.214 离线或探测不可达，请分析。

**预期**

基于真实资产、巡检或探测结果分析各设备状态，区分离线与探测不可达，不把推测写成已确认根因，并给出可核对的下一步。

#### U-FLT-003 业务系统访问异常

**用户输入**

> 业务系统访问异常，帮我做故障分析。

#### U-FLT-004 主备切换后访问失败

**用户输入**

**预期**

围绕主备状态、路径、策略同步和设备配置进行真实查询与分析，给出证据支持的原因或明确未知项，不直接执行策略变更。

#### U-FLT-007 主机安全配置与纳管异常

#### U-FLT-008 数据链路无数据

#### U-QA-002 勒索软件知识库检索

**评估档位：** `fast`

**用户输入**
