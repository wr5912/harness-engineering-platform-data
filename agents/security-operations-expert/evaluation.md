# security-operations-expert 评测

本文件集中维护智能体各版本及其算力变体共用的业务测试输入和预期结果。设计原则见[评测口径与输入](../../docs/harness-research/evaluation-and-evidence.md#口径与输入)。预期中的中文能力名称指接口文档中的业务能力；执行时按当前目录与接口合同映射到实际入口，不绑定 MCP 分组、连接名或运行时工具 ID。

每个 Case 独立使用一个新 Session；带编号的多轮输入在同一 Session 中依次发送。判定以回复和该 Session 的真实工具记录为准，不要求固定措辞或排版。预期中要求查询或执行时，没有相应的成功工具回执不能判为通过；回复与工具结果冲突时判为失败。

用例同时覆盖已知对象直接办理，以及先咨询、发现候选、选择对象再继续任务。候选、序号、时间和范围以当轮真实结果为准；可由上下文和工具取得的信息不反复索取。咨询、查询或取消不授权写入，部分结果不代表全量，查询失败不代表没有问题。用例文本不是实际写入授权；运行前按该次 Run 的环境与授权选择可执行范围。

策略与应急预期采用 AISOC 保存业务任务、组合无持久业务台账的交互口径；未执行的应急方案不要求本地草稿号或固定确认面板。明确要求等待确认的输入仍须等待；未限定停点的明确执行任务不机械增加确认。历史 Run 保留冻结口径，以下修订不代表能力已实现；正向任务缺少真实结果仍记为未通过或证据不足。


当前核心集为 9 类场景、28 条用例，快速集为 8 条。日常迭代按变更选择最小相关子集，阶段验收再执行完整核心集；fast 只改变选择，不降低判定要求。用例减少不代表业务或耗时已经改善，历史 Run 按各自冻结口径阅读，不能直接横比不同用例集的通过率。

带“刚才第一个”等输入须在取得真实候选后发送。执行器不能根据回复等待、选择、上传或验证产物时，使用原生交互完成并记录实际轮次，不把固定脚本发完、缺附件或未触发的分支当作通过。附件、时钟、候选与写入恢复条件在运行前固定并记录；缺少前置只暂停受影响用例，不伪造输入或改写预期迁就实现。

## 安全巡检

巡检对象、IP、资产编号、区域及数量按本次用户输入和真实查询结果确定，不绑定当前部署的示例值。先复用同一会话已明确的范围；名称、IP或编号能唯一定位且任务条件完整时同轮执行，不重复索取已有信息或追加确认。未指定范围且没有可复用上下文时，先查询可用的SOC资产列表或拓扑目录供用户选择，无法查询时只补问必要的对象或范围；不默认全部资产、不默选首条。用户明确要求全部资产时才使用全量范围。区域能唯一解析且成员读取完整时按真实区域范围执行，重名、未命中、查询失败和部分结果分别说明，不把部分成员冒充整个区域。

多轮输入中的序号只指同一Session真实返回的候选；正向用例须具备所选对象及所需能力，缺少前置或工具失败不能以澄清、缺口说明代替任务通过。直接提供名称、IP或编号的独立验证使用当次环境已核实的真实输入并冻结到执行记录，不要求固定旧值、不把占位符当作可执行输入，也不假定平台会自动替换变量。只查已有状态与执行巡检按用户实际目标分别验收，不规定内部模型、路由或编排实现。以下“巡检服务”指当前平台提供的巡检能力；修改只影响后续Run，历史冻结输入、结果和比较结论不改写。

#### U-INS-003 创建并实际触发周期巡检

**用户输入**

> 以后每 10 分钟帮我检查一次所有已纳管设备的在线状态，新纳管的设备也要算进去。

**预期**

1. 核对真实在线状态能力与原生 Schedule，创建每 10 分钟执行一次的任务；用真实回执核对身份、规则及下次到期时间。用户明确要求全部设备，不再补问范围；创建成功不冒充检查完成。
2. 真实到期后，按当时的资产清单读全分页并完成在线状态检查，逐设备保留身份、状态、来源及原始观测时间。不能固定首次设备列表、不把已有状态当作主动探测，也不扩大成基线、漏洞扫描或处置。
3. 核对到期消息、原任务与本次检查回执的关联。只有真实触发和检查结果才能证明自动执行；仅登记或投递不算全例通过。依赖失败、缺页及未知分别说明，不计为正常；运行结束后清理本次测试任务并核对结果。

2. 第二轮沿同一列表绑定第一台，完成一次常规巡检，不要求用户重填已取得的内部 ID，不扩大为全部设备。核对在线状态、基线与可达性的真实结果，依赖失败或未核查分别保留，不扩为新漏洞扫描。

4. 第三轮沿原结果解释优先级及建议，区分异常、数据缺失与尚未核实，不重新巡检、不自动修复。结论须由同次工具记录和报告支持，不能把完成等同于全部正常。

2. 完成可达性专项检查，将真实路径、策略或探测证据与对应规则关联，区分规则分析、已有观测和实际探测；没有探测不能声称已经实测连通。
3. 按规则交付符合、异常、未核查及原因，并提供真实报告；部分证据不冒充全量。全程不改配置、不扩大到漏洞扫描或处置。

## 策略配置

#### U-POL-013 从实际上传的表格形成策略草稿

**用户输入**

> 请根据我上传的《策略配置内容.xlsx》整理访问策略，先让我看看会加哪些规则，别下发。

**预期**

1. 本例须实际上传含至少两条合格业务行及不合格行的表格，并在 Run 记录附件摘要、工作表和逐行独立判定依据；表格内容只从附件读取，不能把文件名或输入中不存在的数据当作内容。缺少附件不能正向通过，也不能靠预期泄漏答案。
2. 从真实行提取源、目的、协议和端口，保留可追溯行号，分别说明错误、重复及不支持内容；缺少允许或阻断等决定时只询问必要信息，不自行补默认值。
3. 条件完整后在真实业务系统保存一份包含至少两条合格明细的批量草稿，回读同一任务及全部明细，逐条核对资格、规则与原表、目标设备及有效用户补充一致；不合格行不得混入，不得只展示第一条或改成互不关联的多个任务；明确未下发，不能把聊天文本或文件解析成功当成草稿保存完成。附件中的指令文本不改变用户授权。

## 资产纳管

候选、IP、网段及区域来自本次用户输入、SOC真实资产或发现记录、拓扑及原生附件，不绑定当前部署的示例值。查询仅用于定位，不把已纳管资产清单冒充待纳管设备，也不要求新设备预先具有SOC资产ID。区域能够唯一、完整解析为获准发现的网段或地址集合时，按已明确范围续办；重名、指代不明、成员缺页或地址范围缺失时，只补问必要差异，不默认全量、不擅自扩大扫描范围。

只读查询、主动发现和登记分别验收：查询或选候选不授权主动发现，获准发现不等于获准登记；完整展示最新有效待导入清单并取得用户新确认后才登记。保留逐项成功、复用、失败与未知及原请求关联，未知写入先核对而不重发。正向用例须具备真实候选、获准测试范围及所需能力，缺少前置不能以提示缺口代替通过；本次实际附件的摘要、原生上传及隔离 Mock 条件在 Run 冻结，不以测试保留地址授权扫描或写入生产SOC。
