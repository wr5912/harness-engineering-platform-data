## 对应处理办法

### A1｜设备离线

适用：SOC离线设备；不是已确认硬件故障

1. 核对资产身份、维护计划和离线／心跳时间；地址无效时先核实真实地址。
2. 同步复查关联业务访问、管理连接和采集心跳，记录各自时间。
3. 定位后恢复对应环节；重启或配置变更前明确业务影响、备份和回退方式。

**结果分支：**
- 业务、管理均正常而心跳异常：检查采集服务、上报连接与认证。
- 业务正常、管理失败：检查管理路径与访问策略。
- 业务失败、管理正常：检查服务监听、业务端口策略与应用依赖。
- 业务、管理均失败：继续核对链路、电源和设备运行状态；不能直接认定硬件损坏。

**验证条件：**取得新的在线和持续采集记录，受影响业务复测通过；计划停机单独记录依据。

### A2｜历史漏洞复核与修复

适用：关联的历史漏洞记录，当前待复核；原严重度不重分级

1. 核实本机软件、版本与部署方式，逐项核对历史漏洞适用性。
2. 逐条结合原修复建议与可信厂商公告确定适用补丁、升级版本或临时缓解；有原严重度时先核对严重、高危记录。
3. 适用条件一致且能共同修复的记录可合并变更，但保留逐设备、逐漏洞关联。
4. 验证兼容性、备份并明确回退条件，经授权实施后另行安排有效复扫和业务验证。

**结果分支：**
- 缺少版本或修复依据：先补查，不生成确定的补丁版本或修复命令。
- 确认不适用：保存版本与适用性依据；需要缓解时区分临时缓解与正式修复。

**验证条件：**修复后的新扫描确认目标漏洞消除且业务正常；本报告仅展示历史记录，不发起扫描或宣称已经修复。

### A3｜基线后续改善与整改

适用：未绑定、未采集状态的可选后续改善；真实基线缺口或已有不达标结论另行核查

1. 核对本机已取得的SOC状态、设备类型及已有基线结论。
2. 取得有效报告后逐项展示检查项、实际值和要求值，依据不合规项制定整改并重新核查。
3. 采集或变更前核对授权、影响与回退条件；保留本机独立复核结果。

**结果分支：**
- 设备未绑定基线模板：后续按需核对系统与服务、选择适用模板；绑定和采集不是完成本次巡检的前提。
- SOC未采集到基线数据：后续按需检查采集条件并安排采集；不要求补采才能完成本次巡检。
- 报告无效或主体不符：核对资产、模板和检测时间，重新取得有效报告。
- 确认不适用：记录适用性依据，不能计为通过。

**验证条件：**如另行实施改善或整改，以对应本机的新报告、实际检查项、有效值、时间和结论复核；未绑定、未采集是已取得的SOC状态，不属本次未完成，也不计正常或通过。

### A4｜业务规则异常

适用：规则或连接关系异常，不等同单台设备故障

1. 核对规则要求、源、目的、服务及实际路径／策略证据。
2. 在授权范围内验证实际访问，明确区分配置关系判断与应用实测。
3. 确认原因后按最小范围修正配置，明确影响、备份与回退条件。

**结果分支：**
- 模型显示同网段二层直达且无中间过滤：先核实拓扑和隔离要求，再评估端口隔离、VLAN或主机访问控制。
- 缺少图层、选择器、路径或策略依据：先补齐证据后重检，不把模型路径结论当作应用实测。

**验证条件：**应允许的业务可用，应阻断的访问被阻断，关联合法业务不受影响。
