## 二、主要差异

| 方面 | 当前实现 | 新版要求及处理 |
| --- | --- | --- |
| 建议生成点 | 基础提示词仍示范 `rule + suggestion`；后置阶段另生成完整候选并替换数组 | 基础阶段仅保留 `[]`，后置阶段唯一生成；同时修改提示词和宿主投影，保留原始回执与偏差记录 |
| 业务门槛 | 误报、可疑直接触发，缺分数也可能进入；人工专项和异常可绕过门槛 | 三种完整结论统一要求有效有限数值且 `confidence_score < T`；首版 `T=0.75`；取消全部例外 |
| 事件绑定 | 旧门槛不检查基础事件 ID；旧参考投影可填入任务 ID 后继续处理 | 先核对本案基础身份、实际五源来源和冻结材料，不能用补写身份证明来源正确 |
| 后置输入 | 规则定义、代表命中、告警与基础参考为主，另行构造和压缩规则上下文 | 复用本轮冻结的 `event_snapshot`、五源业务数据、实际已取得的相关规则信息和采集边界；不得把基础摘要当五源本身 |
| 新增取证 | 后置阶段继续分页查命中、补告警、读完整定义；另保留可选语法目录映射，但不能据此声称已调用这些目录 | 建议分支不新增取证，不因建议再查规则、重做五源或批量取完整定义 |
| 生成目标 | 每个规则目标必须交一项完整候选或 null 诊断 | 围绕有证据的具体问题生成 0–2 条建议，不强求覆盖每条规则、每个层级 |
| 对外内容 | `rule_content / impact_scope / cannot_optimize_reason` | 每项恰为 `rule_level / suggestion / impact_scope`；层级仅“检测规则”或“关联规则”；不含可执行正文 |
| 数量 | 改造前源码公开最多一条，优先首条非空候选 | 生成最多两条；逐项保留通过项并保持其原始相对顺序，不重新排序，不截取超量回执，也不因其他项不合格丢掉通过项 |
| 失败与无建议 | 失败、缺口等可包装为 null 正文建议 | 逐项保留合格项，仅无可交付项时为 `[]`；未触发、无法判断、合法无建议、生成失败、包级全拒、逐项全拒和部分采纳在模型外区分，部分采纳明确拒收数量及安全原因类别，不把诊断当建议 |
| 校验目标 | 目标闭包、候选差异、SOC 正文格式适配等 | 校验三字段、类型、层级、数量、事件绑定；另外核对依据、具体性、重复、风险及伪装正文，结构通过不等于语义通过 |
| 报告与恢复 | 报告直接展示旧三字段 JSON；恢复路径仍要求旧建议形状 | 新 Run 展示自然语言层级、建议与影响，恢复沿同一新合同；旧记录只读兼容，不迁移或重写 |

2. **门槛与阈值。** 精简现有门槛模块；保留严格数值检查和[单一阈值配置](<../../../../evolution/experiments/EXP-security-operations-expert-027-f-r92ea65e6316b/candidate/dsh/managed/threat-analysis/rule-review-policy.json>)。本案来源、身份、结论、分数、阈值缺失或无效时独立记录“无法判断”，不调用后置模型，不填默认分数。基础其他格式问题不是门槛总开关。
3. **后置输入构造。** 按用户后续明确的口径，直接复用阶段1同一份冻结五源，不再次裁剪或重组业务证据，不额外读取审计文件拼装模型输入。已有相关规则信息与来源边界仅使用冻结材料本身所含内容；未说明的原因保持未知，不补猜。已冻结基础结果仅作参考，不把完整性容器、空数组或重复摘要当成真实业务证据。模型外保留必要的事件/摘要一致性核验和运行留痕，不补网络取证或搬整份运行 HOME。

5. **提取和新建议校验。** 精简[响应提取模块](<../../../../evolution/experiments/EXP-security-operations-expert-027-f-r92ea65e6316b/candidate/dsh/managed/threat-analysis/rule_response.py>)及[建议校验模块](<../../../../evolution/experiments/EXP-security-operations-expert-027-f-r92ea65e6316b/candidate/dsh/managed/threat-analysis/rule_validation.py>)，复用严格 JSON 提取、拒绝重复键及非有限值等能力。新项恰有三字段，最多两项，无空对象、空串、null 项或重复占位。“只提供自然语言优化建议”通过生成提示约束，取消代码词形否决，不增加替代内容检测器。坏JSON、重复键、错案、非法封套或原始数组超量属于包级失败，整包拒收；其余合法封套内逐项校验并独立采纳，重复方向保留先通过校验的项、拒收后续重复项。部分采纳明确采用与拒收数量及安全原因类别；逐项全拒时为 `[]` 并记录失败，与合法无建议区分；不静默截断、补字段或新增模型修复轮。语义质量以本案原始依据复核，不用简单关键词或结构合法冒充通过。
